# How to use this resource library

Start with the problem you are facing to find suitable tools, projects to study, and a practical next step.

## Choose an entry point for your question

- **No project yet**: start with the [practical guide](practical-guide.md) to define the deliverable and the smallest playable loop.
- **Want to learn how others build games**: explore the [game cases and source code](../tutorials-and-demos.md), distinguishing author descriptions from material you can actually inspect.
- **Choosing an agent or engine interface**: read the [agent workflows](../coding-agent-game-code.md), remembering that clients, models, Skills, and engine bridges are different layers.
- **Already designing a level**: use the [level-design Skill guide](level-design.md); validate the experience and spatial relationships before adding assets.
- **Preparing validation and delivery**: consult the [testing library](../reference/testing-library.md) and the [production research entry point](../production/overview.md).

## Keep three distinctions when reading

**Existence is not availability.** Code, files, or a demo do not prove that dependencies are complete, that something runs in your version, or that its quality has been validated.

**Running is not publishing.** Code, assets, weights, and services may have different terms; check each before publishing.

**An observation is not a conclusion.** A screenshot, a pass message, or one successful run cannot replace explicit test tasks, states, failure conditions, and actual evidence.

## Language and versions

Formal documentation provides complete English and simplified-Chinese versions with corresponding sections, tables, examples, and references. Code, commands, API identifiers, and source URLs retain their original spelling. Remote historical archives retain their source language and are not presented as Chinese translations.

To confirm tool versions, interface parameters, or usage terms, follow each entry's source links to the official documentation.
