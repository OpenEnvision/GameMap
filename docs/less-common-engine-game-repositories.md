# Released games across Cocos2d-x, Axmol, AGS and Solarus

Primary sources reviewed on 2026-10-22. Five released games extend the collection across programming puzzles, local tank battles, racing and action adventures. Each entry provides gameplay source, a play/build route and the relevant code/content terms. No game was installed, built or playtested.

## Squally — Cocos2d-x / C++ programming-puzzle RPG

- **Repository / status:** [Squalr/Squally](https://github.com/Squalr/Squally), current default branch `develop`. The [finished Steam game](https://store.steampowered.com/app/770200/Squally/) combines side-scrolling exploration, RPG battles and puzzles that let players change in-game x86/x64 instructions to alter mechanisms and world behavior. It was released in 2023 for Windows, macOS and Linux.
- **Useful source:** [Timeline.cpp](https://github.com/Squalr/Squally/blob/develop/Source/Scenes/Platformer/Level/Combat/Timeline.cpp) advances combat action bars, processes state events and resolves victory/defeat. [Laser.cpp](https://github.com/Squalr/Squally/blob/develop/Source/Objects/Platformer/Traps/Laser/Laser.cpp) connects `registerHackables` and `updateLaser` to the laser's modifiable countdown. [SquallyMovementBehavior.cpp](https://github.com/Squalr/Squally/blob/develop/Source/Scenes/Platformer/Components/Entities/Squally/Movement/SquallyMovementBehavior.cpp) handles directional/jump input and saved positions. Useful for studying how editable rules become a concrete game mechanic alongside exploration and combat.
- **Build / assets:** The [README](https://github.com/Squalr/Squally/blob/develop/README.md) documents VS Code/CMake Tools, CMake 3.x (3.31.6 is listed as working), Ninja, Python and platform compilers; maps use Tiled. **Commercial art/audio under `Resources/Private` must be copied from a purchased Steam installation.** The README says store assets match `master`; read current development on `develop`, and use the documented matching source/assets when reproducing the released game.
- **License:** [MPL-2.0 code](https://github.com/Squalr/Squally/blob/develop/LICENSE.md), with separately licensed commercial resources. This is a released game with open code and separately acquired assets.

## Tanks Kombat — Axmol / C++ local multiplayer tank combat

- **Repository / status:** [EugenyN/TanksKombat](https://github.com/EugenyN/TanksKombat), `master`. The [author's release page](https://eugenyn.itch.io/tanks-kombat) provides Windows and Android games with one-to-four-player local battles and computer opponents.
- **Gameplay / stack:** Move tanks through a grid, use walls to block movement and shots, push opponents into pits, collect ammunition and eliminate the other tanks. Rule variants change ammunition, armor and temporary protection after damage. The current source uses **Axmol**, a Cocos2d-x fork; [.axproj.json](https://github.com/EugenyN/TanksKombat/blob/master/.axproj.json) records engine version 2.1.0. The author's older release description still names Cocos2d-x.
- **Useful source:** [GameplayScene.cpp](https://github.com/EugenyN/TanksKombat/blob/master/Source/Scenes/GameplayScene.cpp), especially `onTankKilled` and `roundFinished`, counts remaining tanks, resolves rounds and updates scores. [Tank.cpp](https://github.com/EugenyN/TanksKombat/blob/master/Source/Objects/Tank.cpp) implements grid movement, collisions, shooting, temporary protection and falling into pits. [AI.cpp](https://github.com/EugenyN/TanksKombat/blob/master/Source/Components/AI.cpp) organizes pursuit, attack, retreat and supply goals. A complete short-match example connecting multiplayer rules to state-based AI.
- **Build:** The [README](https://github.com/EugenyN/TanksKombat/blob/master/README.md) documents installing/configuring Axmol, PowerShell and a C++ toolchain, then `axmol build -p win32` or `axmol build -p android -a arm64`. It also describes Visual Studio/CMake and Android Studio routes. Game resources are included, and finished versions are available from the author or repository releases.
- **License:** [MIT code](https://github.com/EugenyN/TanksKombat/blob/master/LICENSE). Art and music are separately credited, including material from older games; the code license does not describe all asset permissions.

## Last'n'Furious — Adventure Game Studio / AGS Script racing

- **Repository / status:** [ivan-mogilko/ags-lastfurious](https://github.com/ivan-mogilko/ags-lastfurious), `master`. The author publishes the complete AGS project for released game version 1.0.4. It is a single-track top-down racer with Safe/Wild physics, two opponent-AI modes, optional car-to-car collisions and checkpoint-based race positions.
- **Useful source:** [RaceAI.asc](https://github.com/ivan-mogilko/ags-lastfurious/blob/master/Last%27n%27Furious/RaceAI.asc) contrasts region-color-based driving with path-node navigation. [Vehicle.asc](https://github.com/ivan-mogilko/ags-lastfurious/blob/master/Last%27n%27Furious/Vehicle.asc) separates forward and sideways velocity, then applies surface grip, braking, drag and collisions. Useful for studying compact arcade handling and simple racing opponents in an engine primarily associated with adventure games.
- **Build:** The [README](https://github.com/ivan-mogilko/ags-lastfurious/blob/master/README.MD) requires AGS 3.4.1 or newer. Preserve the `Last'n'Furious` directory name and open its `Game.agf` in the editor. After the first build, copy the project's `Data` directory into the corresponding `Compiled/Windows` or Linux output directory. The README also explains enabling the in-game AI-path and checkpoint editors.
- **License:** [LICENSE.MD](https://github.com/ivan-mogilko/ags-lastfurious/blob/master/LICENSE.MD) provides game source and original graphics under CC BY 4.0. The IniFile module is zlib; the two music tracks retain their respective attribution terms. This entry refers to the AGS original, whose source is separate from the later XAGE/FNA port.

## Yarntown — Solarus / Lua action adventure

- **Repository / status:** [maxmraz/yarntown](https://gitlab.com/maxmraz/yarntown), `master`. The [official game page](https://www.solarus-games.org/games/yarntown/) offers version 1.0.6 with Solarus 1.6.4. A released, short Bloodborne fan game covering part of the original setting: explore a town, fight enemies/bosses, spend stamina on attacks and dodges, use timed pistol interruptions, and recover lost blood echoes after death.
- **Useful source:** [stamina_manager.lua](https://gitlab.com/maxmraz/yarntown/-/blob/master/data/scripts/action/stamina_manager.lua) implements delayed regeneration after stamina use. [lantern.lua](https://gitlab.com/maxmraz/yarntown/-/blob/master/data/entities/lantern.lua) saves respawn position, restores resources and resets enemies. [lost_echoes.lua](https://gitlab.com/maxmraz/yarntown/-/blob/master/data/entities/lost_echoes.lua) returns the lost currency and clears its saved marker when collected. Together they connect combat resources to the death/recovery loop.
- **Run / package:** Open the published `.solarus` package with the matching Solarus release. Source [quest.dat](https://gitlab.com/maxmraz/yarntown/-/blob/master/data/quest.dat) declares Solarus 1.6. [INSTALL](https://gitlab.com/maxmraz/yarntown/-/blob/master/INSTALL) documents `./install.sh build`, which packages `data.solarus` using zip and generates a launcher that calls `solarus-run`.
- **License:** The [README's license section](https://gitlab.com/maxmraz/yarntown/-/blob/master/readme.md#license) separates GPL v3 game code from graphics, music and `.dat` assets whose rights are reserved. The fan game's code availability does not make the full asset package openly reusable.

## The Legend of Zelda: Mystery of Solarus DX — Solarus / Lua action-puzzle adventure

- **Repository / status:** [solarus-games/games/zsdx](https://gitlab.com/solarus-games/games/zsdx). The [official game page](https://www.solarus-games.org/games/the-legend-of-zelda-mystery-of-solarus-dx/) provides released version 1.12.3. A complete Zelda fan adventure organized around dungeons, equipment, mechanisms and bosses.
- **Version / run:** The published [`v1.12.3` source](https://gitlab.com/solarus-games/games/zsdx/-/tree/v1.12.3) declares Solarus 1.6 in its [quest.dat](https://gitlab.com/solarus-games/games/zsdx/-/blob/v1.12.3/data/quest.dat). Use a matching Solarus Launcher, or `solarus-run .` from the directory containing `data`, following the [official running guide](https://docs.solarus-games.org/tutorials/getting-started/creating-a-quest/). The [release README](https://gitlab.com/solarus-games/games/zsdx/-/blob/v1.12.3/readme.md) documents CMake/zip packaging but retains the historical `solarus_run` command spelling. The current default `dev` branch's [quest.dat](https://gitlab.com/solarus-games/games/zsdx/-/blob/dev/data/quest.dat) instead requires Solarus 2.0.
- **Useful source:** [cane_of_somaria.lua](https://gitlab.com/solarus-games/games/zsdx/-/blob/v1.12.3/data/items/cane_of_somaria.lua) spends magic, uses hero direction to choose a position, aligns it to the map grid and creates a pushable block. [bomb.lua](https://gitlab.com/solarus-games/games/zsdx/-/blob/v1.12.3/data/items/bomb.lua) connects pickup eligibility to the bomb bag and updates ammunition according to pickup variants. Useful for tracing equipment, saved progress and map entities through concrete item mechanics.
- **License:** The current project [license](https://gitlab.com/solarus-games/games/zsdx/-/blob/dev/license.txt) identifies GPL v3 Lua scripts and CC BY-SA 4.0 original data, while separately identifying Nintendo-owned images, sounds and names. Those third-party assets are outside the original-data license.
