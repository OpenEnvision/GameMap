# Sports, racing and puzzle game source

Primary sources reviewed on 2026-10-22. Four released games provide substantial examples of physics-driven controls, level interactions, match rules, replay systems and scoring. These are source-reading guides; no game was installed, built or playtested.

## X-Moto — motorcycle trials and timed runs

- **Repository / status:** [xmoto/xmoto](https://github.com/xmoto/xmoto), `master`. A released 2D motorcycle-trials game: use throttle, braking and rider balance to cross obstacles, collect every strawberry and reach the finish. Timed runs and replays support repeated attempts.
- **Stack:** C++, SDL2/OpenGL, Lua level scripts and CMake, with a custom game framework.
- **Useful source:** [BikeController.cpp](https://github.com/xmoto/xmoto/blob/master/src/xmscene/BikeController.cpp) translates controls into throttle, braking, steering and bike posture. [Scene.cpp](https://github.com/xmoto/xmoto/blob/master/src/xmscene/Scene.cpp), especially `touchEntity`, connects Lua touch events, collectibles, checkpoints and completion conditions. [Replay.cpp](https://github.com/xmoto/xmoto/blob/master/src/xmoto/Replay.cpp) records vehicle state and supports seeking through replays. Together they show how a physical skill challenge becomes a timed, repeatable level.
- **Play / build:** The [official site](https://xmoto.org/) provides Windows, macOS arm64 and Linux AppImage downloads. Start with the [README](https://github.com/xmoto/xmoto/blob/master/README.md) and [Linux build guide](https://github.com/xmoto/xmoto/wiki/Building-on-Linux) for dependencies and the separate build-directory CMake/make workflow; other platform guides are linked by the project.
- **License:** [GPL-2.0 text](https://github.com/xmoto/xmoto/blob/master/COPYING); reviewed gameplay source headers permit GPL-2.0-or-later. Third-party components retain their notices.

## Enigma — marble physics and interactive puzzle objects

- **Repository / status:** [Enigma-Game/Enigma](https://github.com/Enigma-Game/Enigma), `master`. A released top-down puzzle game with over 1,000 original levels. Guide a marble through mechanisms, mazes and hazards to uncover matching colored stones.
- **Stack:** C++, SDL2, Lua/XML levels and a custom object system. Its large content library makes it useful for studying the boundary between level scripting and reusable engine objects.
- **Useful source:** [OxydStone.cc](https://github.com/Enigma-Game/Enigma/blob/master/src/stones/OxydStone.cc) implements opening, matching, closing and paired-completion states through `tryOpen`, `actor_hit` and animation callbacks. [Balls.cc](https://github.com/Enigma-Game/Enigma/blob/master/src/actors/Balls.cc) handles marble behavior; the [level directory](https://github.com/Enigma-Game/Enigma/tree/master/data/levels) shows how actual puzzles compose the mechanics.
- **Play / build:** The [README](https://github.com/Enigma-Game/Enigma/blob/master/README) points to [official downloads](https://www.nongnu.org/enigma/download.html) and documents an autotools build. The [1.30 release](https://github.com/Enigma-Game/Enigma/releases/tag/1.30) identifies the published source version. For the development tree, [CMake notes](https://github.com/Enigma-Game/Enigma/blob/master/doc/README.cmake) list SDL2 libraries, XercesC, ZLIB and CURL, plus `--data` and `--l10n` arguments for running from an IDE. The older `doc/REQUIREMENTS` still lists SDL 1.2; use the current CMake configuration for development dependencies.
- **License:** README specifies GPL-2.0-or-later, with [COPYING](https://github.com/Enigma-Game/Enigma/blob/master/COPYING) providing the license text. External dependencies and sound assets have their own acknowledgments and notices.

## Blobby Volley 2 — arcade volleyball and programmable match rules

- **Repository / status:** [danielknobe/blobbyvolley2](https://github.com/danielknobe/blobbyvolley2), `master`. A released arcade volleyball game with local, computer-opponent and network matches. Move and jump to return the ball while managing contact limits, service and scoring.
- **Stack:** C++, SDL2, custom simulation, Lua rules/AI, RakNet networking and CMake. Useful for separating sports physics from match decisions.
- **Useful source:** [DuelMatch.cpp](https://github.com/danielknobe/blobbyvolley2/blob/master/src/DuelMatch.cpp), especially `step`, connects input, physical events, rules and service resets. [GameLogic.cpp](https://github.com/danielknobe/blobbyvolley2/blob/master/src/GameLogic.cpp) handles contact limits, ball-ground events, points, wins and the Lua rule interface. [PhysicWorld.cpp](https://github.com/danielknobe/blobbyvolley2/blob/master/src/PhysicWorld.cpp) implements ball/player/net movement and collisions.
- **Play / build:** The [official site](https://blobbyvolley.de/) links downloads and a browser version. The [README](https://github.com/danielknobe/blobbyvolley2/blob/master/README.md) documents SDL2, Boost, PhysFS and CMake dependencies, `cmake .`, `make`, and running `src/blobby` from the repository root on Linux/macOS. Windows instructions use vcpkg and Visual Studio. Game data is included in the repository.
- **License:** [GPL-2.0 text](https://github.com/danielknobe/blobbyvolley2/blob/master/COPYING), with reviewed gameplay headers specifying GPL-2.0-or-later; dependency licenses are separate.

## Super Video Golf — released game inside the crogine repository

- **Repository / status:** [fallahn/crogine, samples/golf](https://github.com/fallahn/crogine/tree/master/samples/golf), `master`. This directory contains the source of a released golf game, while the host repository also contains its engine. The game has turn-based shots, multiple scoring formats, local/network multiplayer and a single-player career.
- **Stack:** C++17, crogine ECS, SDL2/OpenGL, Bullet and CMake. Useful for studying shot power/spin, wind and terrain interaction, authoritative match rules and alternative sports scoring systems.
- **Useful source:** [InputParser.cpp](https://github.com/fallahn/crogine/blob/master/samples/golf/src/golf/InputParser.cpp) handles clubs, power, spin and shot timing. [BallSystem.cpp](https://github.com/fallahn/crogine/blob/master/samples/golf/src/golf/BallSystem.cpp) connects wind, spin, terrain friction/bounce and ball state. [ServerGolfRules.cpp](https://github.com/fallahn/crogine/blob/master/samples/golf/src/golf/server/ServerGolfRules.cpp) applies the selected scoring format and resolves outcomes.
- **Play / build:** Finished games are available from the [author's itch.io page](https://fallahn.itch.io/super-video-golf) and [Steam](https://store.steampowered.com/app/2173760/Super_Video_Golf/). **Required game assets are obtained separately from the game and are not fully supplied with the source.** Follow the [root README](https://github.com/fallahn/crogine/blob/master/readme.md), [game README](https://github.com/fallahn/crogine/blob/master/samples/golf/readme.md) and [game CMake configuration](https://github.com/fallahn/crogine/blob/master/samples/golf/CMakeLists.txt) to prepare dependencies/assets and build the `golf` target. The current non-Steam configuration also requires ODIN. The itch.io page says its macOS binary remains at 1.11.0; newer versions require a source build.
- **License:** The game README identifies the source as zlib-licensed and permits using it to make another golf game. Assets have different terms and generally cannot be commercially resold. This is a complete game with open code and separately restricted content.

This repository supplement is linked from the README; it is not part of the exported website catalog.
