# 引擎、渲染库与内容工具

选择游戏引擎来承担运行时与编辑，选择渲染库来实现自定义图形，选择内容工具来生产资产。它们的职责不同：Godot、Unity 和 Unreal 提供引擎工作流；Phaser 面向浏览器 2D 游戏；Three.js 和 React Three Fiber 负责渲染；Blender 创建和处理资产。

## 游戏开发规划的工程指导

- **一起记录版本。** 每项任务都应保留引擎、包、插件、渲染器和文档版本。Godot 演示的 master、Three.js 的 dev 和 Blender 的 main 可能比已安装的运行时更新。API 缺失时，先检查版本。
- **先建立最小项目反馈。** 在加入复杂玩法之前，确认引擎能够启动、资产能够导入、日志可读，并且最小场景能够运行。无头检查、编辑器检查和导出后的运行时覆盖不同的行为。
- **分别观察状态和视觉。** 单元测试检查纯逻辑。跨帧、播放模式或 Functional Tests 检查生命周期行为。截图、输入轨迹和实际游玩评估最终体验。
- **物理问题往往取决于时序和配置。** Godot 的贴地 / 浮空模式；Unity 的 FixedUpdate / Update 时序、接触法线、碰撞层和地面射线；以及 Phaser 的静态物理体刷新都可能影响行为。只重写控制器脚本可能无法消除根因。
- **从 Blender 到引擎的交付是一条转换管线。** 确定单位、坐标轴、对象变换、材质模型、纹理色彩空间、骨骼绑定名称和动画名称。在实际运行时中检查 glTF / GLB 导出与导入。分别验证文件合规性、视觉外观和碰撞行为。
- **Three.js 的灵活性把系统设计决策留给项目。** 渲染库可以与物理、导航、ECS、输入、音频和存档系统组合使用。明确各系统由谁提供。R3F 组织 React 场景；它不替项目选择模拟架构。
- **保留社区经验的复现条件。** 作者教程解释原因和工程权衡。记录版本、测试场景、硬件、源码和失败案例；单个演示或帧率不是能力排名。

MCP 集成和实用智能体技能位于 `agents.json`。游戏 AI 条目维护 Unity 智能体插件和 CLI 的生命周期信息，避免在引擎基础设施中重复计数。
