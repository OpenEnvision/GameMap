# 内容平台：契约、迁移与发布边界

GameMap 的本地开发使用数据库编写结构化内容，配合经过审阅的编辑工作流和不可变网站发布。长篇指南仍以 Git 中的 Markdown 编写。`npm run dev` 预览数据库的当前编辑版本；公共网站和常规生产构建仍读取现有 Git 来源。本地编辑不会发布网站。

## 实现边界

已实现：

- 私有 PostgreSQL 目录、显式成员资格检查、仅追加修订、绑定版本的验证回执、审阅决策、不可变发布清单及冲突安全的激活。
- 内容类型、各类型模式、编写所有权、语言、链接角色及关系类型的注册表。
- 覆盖所有现有类型、原始数据模块、Markdown、翻译、来源信息、附件及源资产的离线导出器与验证器。
- 独立的私有 React Studio：契约驱动表单、来源/附件编辑、显式翻译指纹审阅、修订差异、批量审阅、只读 Git 文档、经验证的预览及冻结发布导出。
- 完整的本地数据库工作数据源，覆盖所有结构化类型、译文、搜索结果、生成指南、下载和被引用的上传媒体。Git 的修改以草稿形式导入并做三方合并，不替换数据库编辑；同一字段的冲突保留在私有报告中。
- 真正的可信编译器：在签发精确修订回执前，验证当前所有载荷/附件模式、规范身份、跨记录引用、媒体校验和、截图尺寸及翻译。
- 通过同源后端集成 Supabase Auth，提供不透明 HttpOnly 会话、服务端 AES-GCM 令牌存储、CSRF/Origin 检查、串行刷新、即时成员资格撤销和权限限定的数据库工作器角色。
- 将完全解码、移除 EXIF、按内容寻址的 WebP 上传到私有文件系统；可移植发布包仅包含被引用的媒体。
- 经验证的发布到注册表读取器和隔离静态站点构建器：选定的数据库修订、经审阅的文档字节、翻译、下载、新记录身份及上传媒体均可进入现有 React Router/Fumadocs 渲染器，不会回退到 Git 业务行。
- 已注册的目录文档生成器、独立审阅的不可变来源索引，以及拒绝陈旧生成指南的冻结门禁。对象映射按规范方式渲染；只有数组承载编辑顺序。
- 无凭据构建子进程、来源/路由/媒体/翻译检查、桌面/移动发布浏览器门禁、带校验和的产物清单，以及显式的仅限开发输出标记。
- 独立的本地精确产物发布器：独立部署登录、不可变产物回执、绑定的私有目标、串行提升、持久崩溃日志、比较并交换激活，以及回滚到保留的字节。其匿名预览不暴露运维文件，也不要求访客登录。
- 快速 SQL/桌面/移动测试套件，以及可选的真实本地 Supabase 验收运行器：PostgreSQL 17 迁移、实际 Auth 和 PostgREST、浏览器登录、刷新轮换、最小权限授权、媒体、显式翻译审阅、独立编辑决策、冻结导出及隔离数据库恢复探测。

尚未实现：云端/预发布部署、默认公共网站/编写来源切换、生产上传/激活工作器、紧急下架，或云对象存储提供方。当前公共网站仍由 Git 驱动。来源同步会将已核实的发起管理员记录为草稿作者；该人员不能批准或拒绝同步的修订。历史上作者为 NULL 的同步记录保留其不可变元数据，但同步审计仍会阻止自审，以及在新的冻结中重用已知经过自审的修订。快速 SQL 套件使用 PGlite、隔离的 `auth.uid()` 垫片及仅供测试的 Auth。`npm run test:local` 则测试真实本地服务，而非这些替代品。两个套件均不证明远程 TLS、云部署或生产运维恢复已获认证。

## 命名与迁移策略

使用稳定的领域名称：`catalog.entries`、`catalog.revisions`、`catalog.content_schemas` 等名称描述职责，而非创建日期、导入批次或临时实现。条目身份是 `kind:identifier`，而不是位置或可变标题。永久表或字段均不使用特定旧来源前缀。

迁移文件名使用连续模式版本， **而非时间戳** 。Supabase 接受数字版本前缀。当前模块为：

| 模块                                 | 职责                                    |
| ---------------------------------- | ------------------------------------- |
| `0001_catalog_core.sql`            | 身份、契约、规范化投影、不可变修订约束及默认拒绝的 RLS         |
| `0002_catalog_workflow.sql`        | 成员资格、经审计的配置、编辑、验证证明及审阅                |
| `0003_catalog_releases.sql`        | 不可变清单、公共发布读取、激活及回滚                    |
| `0004_catalog_imports.sql`         | 私有、幂等、原子的来源导入                         |
| `0005_catalog_registry.sql`        | 初始类型、模式、语言及关系注册                       |
| `0006_catalog_authoring.sql`       | 授权的历史读取及显式草稿翻译                        |
| `0007_catalog_release_context.sql` | 不可变可信构建上下文；激活会拒绝未准备好的发布               |
| `0008_catalog_sessions.sql`        | 私有加密会话存储                              |
| `0009_catalog_revision_order.sql`  | 单调修订顺序，不依赖相同时间戳或 UUID 顺序              |
| `0010_catalog_backend_role.sql`    | 最小权限的 Web/验证器角色，与部署角色分离               |
| `0011_catalog_publication.sql`     | 独立本地部署权限、不可变产物回执/事件、目标绑定及产物级激活        |
| `0012_catalog_sync_authorship.sql` | 归属人工发起的来源同步并防止自审，包括历史上作者为 NULL 的同步记录  |
| `0013_catalog_release_realm.sql`   | 不可变环境/项目/实例/目标绑定、带版本的冻结身份，以及受限的历史本地回滚 |
| `0014`–`0029` | 扩展内容类型、来源导入、游戏和媒体契约及社区工作流 |
| `0030_catalog_source_configuration.sql` | 完整工作目录所需的只读编写元数据，不暴露导入归档 |

这些文件位于 `supabase/migrations/` 下。测试运行器按数字顺序发现文件，并将每个模块固定在迁移包中；不存在硬编码的单文件迁移路径。未来变更应追加新版本。绝不能重命名、重排或编辑已应用于共享环境的迁移。此迁移链仅在隔离本地服务和测试数据库中运行过；目前没有共享或生产部署。早期未部署草稿已合并，但后续模式变更必须追加新的编号迁移。

将三条版本轴分开：

1. **数据库迁移版本：** 有序的 DDL 变更。
2. **包格式版本：** 导入或公共发布的序列化格式。
3. **内容模式版本：** 特定类型的载荷契约。

新的数据集模式不会使每个资源模式都升级，也不会创建带日期后缀的新数据库表。当前导入包使用格式 2；旧草稿包必须重新生成，而不是被静默解释为新格式。

## 所有权与数据模型

此表描述生产来源切换。本地开发已使用数据库修订管理结构化内容；`npm run dev:git` 明确预览保留的 Git 生产输入。

| 内容                         | 切换前                   | 切换后                              |
| -------------------------- | --------------------- | -------------------------------- |
| 结构化资源、案例、研究、路径、集合          | 现有 JSON/TypeScript 文件 | 数据库修订                            |
| 长篇指南及授权技能包                 | Git Markdown 与源资产     | Git Markdown 与源资产                |
| 生成的目录指南及署名台账               | 基于 Git 记录的代码生成器       | 相同的已注册生成器基于已批准发布记录运行；来源索引在冻结前经审阅 |
| 载荷契约                       | 类型定义及字段适配器            | 带版本的定义、可信验证器、带类型的表单及适配器          |
| 网站 JSON、Awesome List、搜索、下载 | 从 Git 生成              | 从一个发布及其固定的 Git 来源生成              |
| 原始媒体                       | 检入文件及来源信息             | 带版本的对象及来源信息；在验证上传前保留 Git         |

文档载荷区分 `sourceMode: git` 与 `sourceMode: generated`，派生视图使用已注册的 `generatorKey`。`git` 编写所有者表示由代码治理的内容，包括可信生成器实现，而非可在浏览器编辑的文章。任何数据库行都不会提供可执行生成器代码。目录指南保留现有地址，不构成第二套手动维护的内容来源。

不要同时为同一集合启用 Git 和数据库编写。这是单向初始导入，而非同步协议。只有在新渲染器证明记录、URL、媒体和两种语言等效后，才能移除旧编写路径。

| 表                                               | 职责                                               |
| ----------------------------------------------- | ------------------------------------------------ |
| `content_kinds`                                 | 稳定类型、标签与编写所有者；不对文档名称做特殊处理                        |
| `content_schemas`                               | 已注册的 `(kind, version, validator_key)` 契约；旧版本仍可寻址 |
| `locales`, `link_roles`, `relation_types`       | 已注册的发现/来源词表，而非固定语言或关系枚举                          |
| `entries`                                       | 稳定身份、规范地址、所有者及编辑头                                |
| `projects`, `project_entries`                   | 经审阅且附有理由的跨类型项目身份；绝不自动合并 URL                      |
| `revisions`                                     | 不可变的带类型载荷与附件，显式绑定类型/模式版本                         |
| `terms`, `revision_terms`                       | 共享分面；现有自由形式标签作为非受控词条保留                           |
| `revision_links`, `revision_relations`          | 精确来源字段、URL 角色及显式引用                               |
| `assets`, `revision_assets`                     | 文件身份、校验和、大小及所属字段                                 |
| `translations`                                  | 语言、所属修订及已审阅源字段的精确指纹                              |
| `memberships`, `validation_receipts`            | 受保护角色及可信的精确内容/模式证明                               |
| `import_batches`                                | 幂等导入及保留的来源归档                                     |
| `releases`, `release_items`, `release_contexts` | 不可变的已批准选择及其精确可信构建上下文                             |
| `studio_sessions`                               | 不透明会话 ID、加密 Auth 令牌及固定会话过期时间                     |
| `deployment_state`, `audit_events`              | 当前成功发布指针及仅追加的操作历史                                |

修订的 JSON 正文包含 `title`、`summary`、带类型的 `payload` 及 `attachments`。模式版本是具有外键的显式关系列，而不是重复的可编辑正文字段。共享/可查询的关注点各有独立的关系数据所有者。这并不意味着允许将任意未经验证的 JSON 放入生产环境。

`website/content/contracts.ts` 是运行时载荷/附件契约。TypeScript 模型从中推导，Studio 表单 JSON Schema 也从相同定义生成，而不是单独维护。显式安装的 `V1` 处理器保留自身验证器键，不跟随活动编写指针；添加 V2 时必须保留 V1，并包含相应的组装/展示支持。`models.ts` 声明所有权、活动模式版本及验证器键。`scripts/lib/catalog/adapters.mjs` 隔离各类型策略；`projection.mjs` 将其规范化；`validation.mjs` 执行可信检查；`worker.mjs` 提交冻结投影和回执。`assembly.ts` 将选定修订重新组装为现有带类型注册表，不回退到旧业务行。未知类型/版本按失败即关闭原则处理。

首次导入会在旧媒体元数据缺失该值时，明确原始语料已记录的浏览器捕获来源。新编写的游戏预览必须注明来源；创作者截图必须保留原始图片 URL。原始语料已记录的编辑美术署名也会在导入时明确。新美术作品和项目图片需要各自署名，防止渲染器将上传的第三方美术重新标为 GameMap 作品。完整的正文到渲染器往返验证会拒绝相互矛盾的录像来源信息或被静默丢弃的附件字段。这些措施均不会推断项目创作者、授予重用权，或证明项目已被游玩。

来源归档保留片段成员关系、研究封套元数据、原始录像、创作者/客户端署名、媒体权利、审阅范围及界面翻译。导入的来源审阅不等于复现、独立作者身份核实、许可批准或发布批准。

## 安全扩展内容

### 添加内容类型

例如，数据集、活动或课程不应要求再复制一个目录，或修改核心身份/工作流表：

1. 定义其带版本的运行时载荷/附件契约，并推导 TypeScript 模型。声明其 `ContentKindDefinition`，包括所有者、模式版本及可信验证器键。
2. 定义其字段展示、引用、来源所有权及来源清单。
3. 添加各类型导入策略。公共哈希、文件处理、导入事务及发布逻辑保持不变。
4. 在新的编号迁移中注册类型和模式。受保护的注册如下：

```sql
insert into catalog.content_kinds(kind, label, owner)
values ('dataset', 'Dataset', 'database');
insert into catalog.content_schemas(kind, version, validator_key)
values ('dataset', 1, 'gamemap.dataset');
```

5. 在 `versionedContracts` 中注册可信处理器，实现其组装/展示适配器，并测试源、渲染及搜索覆盖。Studio 从运行时模式生成受支持的字段表单；特殊字段类型仍需显式 UI 适配器。未知 UI 版本为只读，不会使用错误契约编辑。仅在数据库注册不会创建渲染器。

仅当新的可查询关系或约束需要时，才添加领域表。在同一迁移中使用 `catalog.secure_tables()` 保护新表。不要按来源、导入批次或日历日期大量增设表，也不要为在另一页面展示已有项目而复制它。

### 演进载荷

注册 `(kind, version + 1)`，并部署理解该版本的验证器/适配器。升级会创建具有新显式模式版本的后继修订，而不会改写旧载荷。两个版本可独立审阅和冻结。回执不能跨类型、版本或内容摘要重用。

设置 `enabled_for_writes = false`，阻止编辑者使用旧版本创建新草稿。其旧修订及冻结发布仍可读取。现有模式契约的身份不能就地更改。停用写入契约不能代替紧急安全撤回。

### 添加语言或关系

注册语言区域、关系类型或 URL 角色，而不是改写 CHECK 约束。翻译投影会遍历 `translationCatalogs` 中以语言区域为键的目录，验证每个来源指纹。源 UI 目前支持英文和中文；另一个已注册数据库语言仍需实际 UI 消息、路由、翻译目录及浏览器测试。

编辑状态机有意保持严格且共享。可扩展内容不意味着用户自定义状态可以绕过批准、验证或权限。

## 编辑与授权

```text
save successor → draft → submit → in_review → approved or rejected
                                      ↓
                      exact trusted validation receipt
```

- 每次保存都要求预期编辑头；陈旧编辑者会收到冲突。调用方显式提供载荷模式版本。
- 规范身份与编写所有权受保护。任何 Git 所有的类型在数据库编辑器中均为只读。
- 编辑者提交自己的修订；管理员可提交导入草稿。审阅者不能对自己的修订作出决策。
- 批准要求可信回执，绑定内容摘要、类型、模式版本及已注册验证器键。
- 经验证的投影、历史内容、回执、发布及审计历史均不可变。要修改请保存后继修订。
- 即使原网站已显示记录或其来源已检查，导入仍创建草稿。

表保留在私有 `catalog` 中，启用 RLS 且不给浏览器授权。不要将其添加到 PostgREST 暴露的模式。匿名访客只能调用 `catalog_published_release`；编辑 RPC 有显式授权。成员资格来自 `catalog.memberships`，而非浏览器可控的个人资料元数据。数据库管理员可为已有 Supabase Auth 用户配置资格，例如：

```sql
insert into catalog.memberships(user_id, role)
values ('REPLACE_WITH_EXISTING_AUTH_USER_UUID', 'editor');
```

成员资格变更会接受审计。私有函数初始仅所有者可用；撤销的是 PostgreSQL 全局默认 PUBLIC EXECUTE 授权，而不只是保留全局授权不变的模式级默认值。显式授权仍是允许列表。

Web 后端在私有事务中始终使用 `catalog_backend`，在请求 RPC 中使用 `authenticated` 并提供经核实的 Auth 用户 ID。工作器可读取目录、暂存经验证的投影、追加 Git 所有的来源修订及附加构建上下文。它不能配置成员、更改契约、直接批准行、更新部署指针或执行 `catalog.activate_release`。它也不获授首次导入权限。部署服务仍是独立的特权调用方。

在源代码控制之外配置专用数据库登录，不继承所有者权限，并授予 `catalog_backend`。本地设置也如此；数据库所有者凭据和服务密钥均不应放入 Studio 服务器配置：

```sql
create role gamemap_studio_login login noinherit password 'SET_A_PRIVATE_PASSWORD_OUTSIDE_GIT';
grant catalog_backend to gamemap_studio_login;
```

为该登录使用受保护的连接 URL。远程数据库 TLS 证书会被验证；如有需要，使用 `NODE_EXTRA_CA_CERTS` 配置可信 CA，而不是禁用验证。绝不能向浏览器暴露数据库凭据、会话机密或服务密钥。

## 本地工作目录

完成本地配置和待应用迁移后，运行 `npm run studio:dev` 编辑内容，运行 `npm run dev` 预览网站。网站在一个只读事务中读取所有数据库所有者条目中最新的未被驳回修订及其译文，包括草稿；本地 Supabase 验收运行器创建的记录不在其中。每两秒检查变更，准备一份完整工作输入。任何内容类型都不会叠加到 Git 业务记录上。目录元数据来自数据库的活动发布上下文或初始导入；当前 Git Markdown 和可信生成器仍由代码管理。

Vite 服务器使用当前界面展示数据库内容。它的生成输入、准备好的文档和路由写在 `.build/catalog-local/development/content/`，与构建使用的 `website/.content/` 分开，因此预览运行期间可以同时构建。下载文件和被引用的私有上传暂存在 `.build/catalog-local/development/public/`。这些都是可重建的视图，不是编写来源。凭据保留在本地后端配置中。预览仅监听本机；编辑头不是发布批准，也不是可部署的发布产物。

已有数据库缺少后来添加的 Git 记录时：

```sh
npm run local:backup
npm run local:migrate
npm run local:import
npm run local:import -- --apply
```

来源补录通过现有原子导入流程，将缺失的数据库所有者记录导入为草稿。两边都有的记录，以该记录上次吸收的 Git 版本为基线做三方合并：基线是它的第一个修订，或上一次合并记录在 `.build/catalog-local/imports/git-base.json` 中的版本。只有 Git 改过的字段采用 Git 的值，数据库改过的字段保留数据库的值；两边改法不同的字段连同基线、数据库和 Git 三方的值写入报告。可在 Studio 中处理，也可以在 `--apply` 时用 `--keep-database KEY,...` 或 `--take-git KEY,...` 记录决定；决定会在下次合并时沿用。`--restore-translations` 会补回记录丢失、但仍与当前英文对应的 Git 译文，例如保存后继修订时漏带的译文。按游戏画面契约，Git 中经审阅的实机画面优先于数据库的后备页面封面：完整的实机画面记录把被替换的封面保留为归档封面，否则封面留在修订历史中。合并结果由本地管理员经 Studio 草稿接口保存，并对当前编辑头做比较并交换。导入不提交、不审批、不发布；Git 和数据库都没有新变化时，重复执行不会改动任何内容。此路径不导入 Git 所有者的文档记录：工作预览直接读取当前 Markdown，冻结发布仍保留经审阅的文档工作流。

`npm run dev:git` 不连接数据库，仅预览 Git 生产输入。`npm run build`、Pages 工作流和发布激活均与工作预览分离。

## 运行私有 Studio

Docker Desktop 运行时，可复现的隔离本地流程为：

```sh
npm ci
npm run local:start
npm run local:setup
npm run studio:dev
```

固定版本的开发 CLI 使用项目 `gamemap`，从不链接云项目，并应用编号迁移。进程本地 Docker 包装器将每个发布端口显式绑定到 `127.0.0.1`；仅靠网络默认设置对固定版本 CLI 并不足够。运行器检查实际容器绑定，若任何端口暴露到局域网，便停止服务栈。它拒绝远程 Docker 套接字及非回环服务 URL。私有实例标记固定此检出目录及其数据卷；已有但尚未认领的项目绝不会被静默接管或停止。请使用这些包装器，而非直接运行 `supabase start`。

`local:setup` 配置真实本地 Auth 管理员/编辑者/审阅者账户及用于拒绝测试的非成员账户，只向专用 `NOINHERIT`/非超级用户数据库登录授予 `catalog_backend`，将原始语料导入为草稿，并创建私有且被忽略的 `.env`，不会覆盖不相关的已有文件。随机密码和服务凭据保留在被忽略的 `.build/catalog-local/` 下，并设置私有目录/文件权限。在本地读取 `.build/catalog-local/access.json` 获取测试账户密码；不要粘贴或发布它。重新运行设置不会覆盖内容。对于手动配置的预发布服务，请改用 `.env.example`。

```sh
npm run local:status
npm run test:local
npm run local:stop
```

可选验收运行器使用实际 Auth/PostgREST/PostgreSQL，包括真实浏览器登录及串行的真实刷新令牌轮换。其合成记录和显式夹具批准属于 **本地测试决策，不是事实审阅或生产批准** 。即使 Git 检出干净，冻结上下文也始终记录 `environment: local`；这些发布无法生成生产产物。运行器仅测试本地数据库激活/CAS，不测试公共网站部署或产物匹配的回滚。`local:stop` 保留本地数据；它不会重置或删除卷。

UI 默认地址为 `http://127.0.0.1:5174`，并在端口 4180 代理其同源 API。没有凭据时显示设置说明；没有演示账户或认证绕过。唯一的伪 Auth 实现位于 `tests/helpers/` 下，由隔离内存数据库支持。真实入口和浏览器构建都不会导入它。

服务器需要 `CATALOG_DATABASE_URL`、`SUPABASE_URL`、`SUPABASE_PUBLISHABLE_KEY`、至少 32 字符的随机生成 `CATALOG_SESSION_SECRET`，以及指向独立配置的运维身份文件的 `CATALOG_RELEASE_REALM_FILE`。启动时会将该文件与数据库不可变领域比较，然后才处理已配置请求。任何变量都不使用 `VITE_` 前缀。Auth 访问/刷新令牌加密存放于私有会话行；浏览器收到的是不透明 HttpOnly、SameSite=Strict cookie 和 CSRF nonce，而非 JWT 或刷新令牌。变更要求配置的精确 Origin 和 CSRF 头。撤销成员资格后，下一个受保护请求即被拒绝。轮换会话机密会使会话失效，但不改变内容。

```sh
npm run studio:build
npm run studio:start
```

`studio:start` 是生产入口。应部署匹配的源检出及 Node/Git 运行环境，而不只是静态 `dist/` 目录。可信 TypeScript 编译器与 Markdown 解析器是运行时依赖；构建 Studio 后支持 `npm ci --omit=dev`，CI 会单独检查。它要求位于可信 TLS 反向代理后的 HTTPS Origin，以及仓库外的绝对路径持久化 `CATALOG_MEDIA_ROOT`。本地开发可使用被忽略的 `.build/catalog-media`；生产环境不要使用该临时目录。媒体根目录不能是公共源目录，也不能是指向公共源目录的符号链接。应将此私有卷与数据库及匹配源修订一起备份。上传接受不超过 10 MB 的 PNG/JPEG/WebP，在 4000 万像素内完全解码，保留方向、移除 EXIF，并转换为以内容哈希命名的无损 WebP。拒绝 SVG 上传；源徽标仍是只读且经验证的资产。只有被引用的本地资产才进入导出发布。图片必须是带版本的本地资产；原有外部托管视频保留带署名的引用，而非未经许可复制。包校验和不覆盖其字节及持续可用性。视频字段绝不提供图片上传器，包含嵌入式凭据的 URL 会被拒绝。

Studio 不提供账户注册或激活按钮。编辑者保存不可变后继修订、显式审阅过期翻译、验证并提交。审阅者检查变更并记录决策；不能审阅自己的修订。管理员可提交导入草稿及同步 Git 文档索引。来源同步读取发现的公共 Git 文章，并从已批准数据库选择重新生成已注册目录视图。它追加并验证变更的索引，将其保留为草稿；既不改写 Git 检出，也不批准索引。审阅者可在私有预览中检查精确的完整 Markdown，以及相应 Git/生成器变更。批准结构化变更后，在冻结前同步并审阅变更的目录索引；陈旧的生成 Markdown 会阻止发布。

更改运行时契约或 Git 源文档后，重启 Studio。冻结上下文固定编译器/来源哈希；检出变更后会被拒绝，而非静默使用不同代码。预发布和生产要求生产安全模式、干净且已提交的源代码，以及各自注册的领域。`NODE_ENV` 绝不选择或改变领域：即使使用生产安全设置，本地数据库仍冻结为本地发布。干净检出不能将本地验收夹具变为获授权的生产发布。

### 不可变发布领域与升级

运维人员注册且只注册一个环境（`local`、`staging` 或 `production`）、项目键、数据库实例 UUID 及逻辑发布目标。注册不可变，且仅当值完全相同时才幂等。`catalog.initialize_release_realm` 仅所有者可用：Studio、浏览器角色、服务角色和部署者不能初始化、更改或接管身份。未绑定数据库不能冻结。非本地注册必须先于任何现有审阅/发布历史；本地批准绝不能导入新的真实环境。

迁移 `0013` 不猜测环境。新的 `local:setup` 会显式初始化所属本地项目。升级已有本地项目：

```sh
npm run local:migrate
npm run local:realm-setup
# Add the printed CATALOG_RELEASE_REALM_FILE path to the private .env, then restart Studio.
```

非机密的 `.build/catalog-local/realm.json` 是运维预期，而不是凭据或提供方签名。Studio 将其与数据库比较；`site:build --realm FILE` 将其与冻结清单/上下文比较；本地发布器将其与数据库和产物比较。不要接受不可信包发送方提供的目标文件。复制的数据库保留其身份；它不是新的预发布项目。真实的提供方/项目隔离仍须独立验证。

新冻结清单、构建上下文及站点产物证据使用版本  **2** ，并携带相同领域。发布包封套仍为版本  **1** ；各类型模式及导入包序列化是独立版本轴。冻结修订在构建前绑定逻辑目标，而本地发布器仍只接受本地开发产物。不同本地 basename 可为同一目标生成不同产物；未来托管适配器还必须强制其实际仓库/Origin/基础路径配置。

历史版本 1 的字节绝不重新标记或改写。现有公共交付仍可用。只有在 `0013` 之前已激活、被记录在其不可变本地历史允许列表中，且仍匹配原始实例/目标/根目录及回执的产物，才可在本地恢复或回滚。未激活的旧产物和旧包不能获得新的发布资格，也不能通过新构建器重建。请改为冻结新的领域绑定发布。即使尚未认领文件系统目标，原始 `catalog.activate_release` 兼容路径也已禁用。

浏览器 JSON 导出是元数据加冻结文档文本，不是媒体备份。使用受保护的运维凭据创建并验证可移植私有包：

```sh
npm run studio:export -- --id RELEASE_UUID --out .build/releases/reviewed
npm run studio:verify -- --input .build/releases/reviewed
```

这会写入 `release.json`、报告及带校验和的被引用本地文件。原始外部视频 URL 仍为引用，不打包为媒体。它拒绝已有输出目录和公共/源目录。验证是离线的，要求匹配的源检出。这些命令不会批准、构建、上传或激活任何内容；摘要是完整性证据，不是签名，也不是部署不可信包的许可。

### 本地备份与恢复演练


本地备份使用一个导出的可重复读 PostgreSQL 快照捕获 `auth`、`catalog` 及目录公共 RPC，同时保存带校验和的私有媒体、允许列表限定的匹配源代码树，以及私有运行时配置。其中含凭据和 Auth 数据：整个被忽略的备份目录必须保密，绝不能放入发布包或静态产物。清单固定 SHA-256 文件哈希和每表行清单。

## 从经审阅发布构建网站

常规 `npm run build` 和 Pages 工作流仍由 Git 驱动。发布构建是显式隔离路径，而非应用到工作树的环境开关：

```sh
npm run site:build -- --input .build/releases/reviewed --out .build/site-artifacts/reviewed --realm OPERATOR_REALM_FILE --base /GameMap/ --browser
npm run site:verify -- --input .build/site-artifacts/reviewed
```

预发布/生产产物要求精确冻结的 Git 提交、干净检出、匹配且独立提供的领域、非脏冻结上下文，以及浏览器门禁。仅对私有本地夹具，传入 `--realm .build/catalog-local/realm.json --development`；公共网站清单及产物证据会明确标为开发输出。完整性验证不是签名或部署授权。

构建器先验证包，再创建私有临时检出，物化一个快照提供方，绝不从 Git 默认值补齐缺失行或翻译。它使用经审阅的文档正文，推导全部结构化下载，将原始及上传媒体通过部署 basename 处理且仅处理一次，并默认保留每个现有身份/地址。撤回或地址迁移需要独立显式策略，而不是静默缺页。工作区使用后会移除；已有产物目录绝不覆盖，开发者检出中的 `dist/` 不受影响。

构建子进程不会收到 Supabase、数据库、会话或 Vite 前缀凭据。所有文档以 Markdown 编译，而非可执行 MDX 表达式。活动 HTML、不安全的 Markdown 链接协议及夹带到生成目录文章中的图片嵌入会被拒绝；二进制媒体应放在带类型的附件中。原始外部视频引用仍为带署名链接，而非镜像文件。

成功输出包含 `site/`、`build.log` 及完成记录 `evidence.json`，其中有精确发布身份、Git/来源身份、已执行门禁和完整的带校验和文件清单。失败日志/部分输出不是已完成产物。提升前验证精确清单；保留此产物用于回滚，而不是用较新代码重建旧发布。这些命令不会上传、激活或更改成员资格。

仅供 CI 的 `tests/helpers/release-fixture.mjs` 创建隔离数据库/Auth 夹具，其中包含仅存在于数据库的记录、中文文本、上传像素及字面上形似表达式的文章。生产代码绝不导入它；其开发产物不得部署。

## 本地精确产物发布与回滚

这是 **本地演练** ，不是 GitHub Pages 部署或编写来源切换。它只接受通过浏览器检查且发布/上下文摘要匹配不可变本地数据库行的开发产物。生产冻结产物会被拒绝。Studio 后端和浏览器绝不获得部署凭据或激活端点。

```sh
# Existing local stacks: append pending migrations without resetting data.
npm run local:migrate
npm run local:publisher-setup
npm run local:publication-status

# Use the predecessor artifact/release reported by status; use none only for an empty pointer.
npm run local:publish -- --input PRIVATE_SITE_ARTIFACT --expected EXPECTED_ARTIFACT_OR_none --expected-release EXPECTED_RELEASE_OR_none --run operator-reviewed-local-run
npm run local:publication-serve -- --port 4191

npm run local:rollback -- --artifact PREVIOUSLY_PUBLISHED_ARTIFACT --expected CURRENT_ARTIFACT --expected-release CURRENT_RELEASE --run operator-reviewed-local-rollback
npm run local:publication-recover
```

私有目标是 `.build/catalog-local/publication/`；若产物 basename 对应此路径，可访问匿名预览 `http://127.0.0.1:4191/GameMap/`。只提供已提交交付指针的网站文件，绝不提供回执、日志、凭据或旧 HTML。`dist/` 和 Pages 工作流均不会被替换。独立 `NOINHERIT` 登录存放在私有 `.build/catalog-local/deployer.json`，而非 `.env`、Studio 或浏览器包。它不能编写/批准内容、配置成员或读取私有 Auth/会话表。

首次使用时，数据库目标和文件系统标记将规范私有目录绑定到该数据库实例。PostgreSQL 会话咨询锁覆盖复制、SQL 提交和日志清理；另一运维人员不能交错切换。发布器严格验证并将产物清单中的文件复制到保留目录，同步字节/目录，写入持久意图，原子重命名 `current` 符号链接，验证切换后的产物，然后才使用两个预期前驱身份激活发布/产物。独立原子的 `published.json` 指针在 SQL 提交后更新，因此提升期间匿名读者仍看到完整旧网站。同一发布的两次构建仍具有不同产物身份。早期仅限服务角色的发布指针路径即使在目标绑定之前也已禁用；它不能绕过产物绑定发布。

文件和 PostgreSQL  **不是一个分布式事务** 。若进程在 SQL 提交前终止，恢复会还原此前文件指针。若提交后、确认/清理前终止，恢复则保留已提交产物。结果不明的失败会保留日志；恢复读取已提交数据库状态，而非从文件猜测。意外的第三方指针或受损保留字节会使恢复停止以便调查，而不是静默覆盖。回滚只使用此前激活且重新验证的保留产物；绝不使用较新源代码重建旧内容。切换期间，每个请求使用一个完整快照；缓存页面/资产及 CDN 全局原子性仍是生产适配器需要解决的问题。

```sh
# First produce a real local reviewed fixture package, then exercise publication.
npm run test:local
npm run test:local:publication
```

发布验收会构建同一真实发布的两个经浏览器检查的变体，并测试独立运维人员、陈旧产物 CAS、匿名读取、精确回滚，以及切换后、提交前和提交后的实际进程终止。这些明确属于本地测试操作，而不是生产编辑/部署授权。

备份活动发布器时，应保留发布产物、目标标记及任何待处理日志。单独的数据库/媒体/源代码恢复探测不会恢复此文件系统状态，也不能证明成对生产恢复已达标。不要手动删除 `current`、改写回执或移除待处理日志来强行部署。

## 导出、验证与导入

```sh
npm ci
node scripts/build/generate.mjs
npm run check
npm run platform:export -- --out .build/catalog-import
npm run platform:verify -- --input .build/catalog-import
```

导出是离线的：不连接 Supabase，不进行外部下载、批准或发布。输出必须是新的私有目录；不会覆盖已有包。

| 文件            | 内容                         |
| ------------- | -------------------------- |
| `bundle.json` | 格式版本、已注册契约、保留来源、规范化投影及摘要   |
| `report.json` | 各类型清单、模式版本、语言区域、警告及可能的项目匹配 |
| `import.sql`  | 用于已迁移且已备份数据库的事务性导入         |
| `files/`      | 带校验和的源文件及非 Markdown 文档产物   |

ID 与规范路径保持不变，包括含斜杠的研究标识符和锚点。共享项目 URL 只是审阅建议，不会自动合并。来源链接保留其字段，不会自动标为官方证据。

验证使用独立加载的本地清单、原始来源/模块/迁移哈希、归档 Markdown、翻译指纹及复制的文件字节。归档 JavaScript 绝不执行。验证旧包时，使用匹配的检出及源编辑；Git 提交不描述未提交文件。完整性摘要不是签名，也不是发送方可信的证明。

包包含草稿、来源归档和可执行 SQL。不要公开提供它们，也不要盲目执行贡献者提供的包。先审阅报告、验证包、备份数据库，在隔离本地/预发布环境应用迁移，然后通过受保护连接应用 `import.sql`。继续前应核对记录、ID、路径、模式、来源信息、翻译和资产校验和。

导入是原子的。相同重新导入为空操作；不同包的重叠身份会被拒绝，而非覆盖编辑。未知契约或不匹配注册声明会失败。刷新已有内容的目录需要显式基于修订的迁移，而非再次首次导入。文件只被复制，不上传到 Storage；在验证上传校验和及署名前保留原始媒体。

使用 `local:start` 和 `local:setup` 运行隔离的 Docker 项目。固定版本 CLI 是开发依赖，配置禁用公开注册与自动种子填充。不要为了刷新导入而重置已有编写数据库，也绝不能在生产环境运行 reset/push/link 命令。

## 发布与切换门槛

审阅者冻结已批准且验证的修订及固定 Git 提交。缺失引用和重复条目版本会失败。冻结清单捕获选定模式契约与词表，而非指向它们的可变指针。它不包含私有来源归档、成员资格和审阅备注。冻结不等于发布。

发布存储精确的 `manifest_text` 字节及其 SHA-256 摘要，还存储独立哈希的不可变构建上下文，其中包含精确选定修订 ID/摘要、配置、编译器哈希、公共 Markdown 及资产引用。激活会拒绝没有匹配上下文的发布。解析前对这些字节计算哈希；重新序列化的 JSON 可能具有不同字节。隔离构建工作器使用固定 Markdown 渲染该精确发布，并验证资产以及源/渲染/浏览器检查。本地受保护发布器现在会在激活前提升该精确产物，提供持久恢复及预期发布/产物前驱。未来生产适配器必须提供等效的受保护上传及独立核实的部署证据。较早的慢速构建不能覆盖较新激活。回滚也需要匹配的已部署网站产物；仅改变数据库指针不会恢复文件。

静态快照无法保证从缓存或离线页面即时撤回。紧急拒绝列表或在线门禁仍是独立要求。

[离线预发布就绪性审查](staging-readiness.md)记录剩余环境/托管/恢复阻碍及已禁用的规划配置。准备此配置不等于云集成，也不授权更改当前 Pages 工作流。

将公共生产目录切换到数据库发布之前：

1. 在受保护预发布环境重复已运行过的真实本地 Auth/数据库验收，包括远程 TLS、账户配置及运维配置。本地成功不是云集成认证。
2. 使用真实且经审阅的预发布目录运行隔离发布构建器，核对迁移结果，并在移除 Git 编写路径前批准编写来源切换。本地夹具等效不授权生产切换。
3. 将已在本地测试的受保护发布器扩展到生产托管适配器，在真实托管/CDN 约束下提供部署证据、成对备份/恢复演练、故障恢复及精确产物回滚。Web 角色必须始终不能激活发布。
4. 添加紧急撤回机制；如有需要，添加具有等效校验和及访问保证的云对象存储适配器。
5. 每个集合的编写来源只切换一次，并保留只读迁移/来源归档。

这些门槛通过之前，公共生产构建继续使用 Git 来源。本地数据库编写和工作预览不代表生产 CMS 已部署。
