# 内容模型与覆盖范围约定

某个游戏写在源数据分片里，搜索却找不到时，沿着它的固定 ID 查。先看分片是否汇入所属集合，再看详情页有没有构建出来，最后查搜索索引有没有这条路由。条目可以通过源数据校验，却在中途某一步漏掉。如果只缺中文字段，沿用同一个 ID，先核对翻译指纹，再查页面组件。

## 权威定义

| 定义                                       | 职责                                                |
| ---------------------------------------- | ------------------------------------------------- |
| `website/content/contracts.ts`           | 带版本的运行时载荷及附件验证，以及推导出的 TypeScript 模型 |
| `website/content/models.ts`              | 内容类型、各类型的模式版本、编写所有者、验证器键、展示区块及注册表 API             |
| `website/content/assembly.ts`            | 重新组装选定的数据库修订，不从 Git 补填缺失的业务行                      |
| `website/content/source-data.ts`         | 导出本地开发与生产构建使用的仓库数据和翻译覆盖层 |
| `website/content/generators.config.json` | 已注册的派生文档地址与可信源渲染器；不包含可执行的数据库配方                    |
| `website/content/sources.config.json`    | 每个数据模块、运行时导出、片段、附件及元数据的所有者                        |
| `website/content/site.ts`                | 路由定义、规范 URL 辅助函数及导航                               |
| `website/content/fields.ts`              | 完整的字段展示定义，或有文档说明的结构性用途                            |
| `website/content/registry-core.ts`       | 无覆盖地规范化源记录，验证身份与引用，推导清单                           |
| `scripts/lib/documents.mjs`              | 递归发现 Markdown；标签不能排除文档                            |
| `website/content/registry.server.ts`     | 服务端/构建注册表；路由仅序列化其视图所需的数据                          |
| `website/content/taxonomy.json`          | 共享的类别、阶段、资源类型及访问类型定义                              |

面向读者的区块包含解释、说明、链接、署名及相关限制。审计日期、内部标志、修订哈希和数字 ID 等技术元数据保留在源记录和发布的内容清单中；不会作为额外详情面板渲染，也不会加入全文搜索。创作署名、许可类别、审阅状态和执行状态仍作为面向读者的来源信息。

资源目录、游戏示例、智能体工具包、测试库、开发路径、项目录像、发现集合和仓库研究仍是不同的类型。研究候选项不会被静默提升为策展资源或已验证可玩案例。引擎基础资料不会被标为 AI 创作的游戏。

## 身份与所有权

每条实质记录都有稳定的 `kind:id` 键。公开记录还具有规范 URL 或锚点，以及所属集合。ID 由作者指定，不从数组位置或可变标题生成。重复键和规范地址是错误，而不是以后写覆盖先写的赋值。

开发路径（`path`）及其步骤（`step`）仅供内部内容编写使用。它们的源数据、稳定身份和内容清单条目仍接受验证。保留的 `/paths/` 地址用于标识这些记录，不作为公开路由。这两类记录不出现在公开导航、预渲染页面或全局搜索中。

开发步骤属于某条路线，并保留独立的描述、交付物和检查点字段。测试入门项保留任务和测量字段。案例署名记录创作者证据；关联资源链接或模型名称并不能证明所用的编码智能体客户端。

数据片段会独立于其聚合导出接受检查。在片段中添加案例却忘记加入图库，必须导致检查失败。新数据文件和运行时导出需要显式声明来源处置方式。模式标签、身份资产、截图和美术作品都有声明的所有者，而不是成为未计数的并行目录。

## 录像是一对多关系

一个资源可以有多个精选片段和原始项目录像。注册表不会仅按资源 ID 索引录像，也不会为了选择首选片段而修改原始视频或海报集合。

`website/src/data/recordings.ts` 对每部原始影片只编写一次记录，并在其中嵌套具有明确标识的展示版本。一个资源可引用多个原片，每个原片也可有多个节选或响应式版本。资源页面会将共享原片分组，而不是重复同一电影卡片。此前的每个展示 URL 和署名仍可访问。原始链接、创作者署名、提示词、替代预览及响应式变体都会保留。预览需要用户主动播放；绝不自动播放。

## 文档与搜索

`docs/` 下及仓库根目录中的每个 Markdown 文件——包括手动维护的 README、完整目录和贡献指南——都会被自动发现。配置的分组提供标签与顺序；未配置的文档显示在“更多笔记”下。缺失的已配置来源和重复 slug 都是错误。

注册表为公开记录的导航、规范链接、静态路由及全局搜索提供数据。首页导航直接通向各记录的所属集合，不另设全量内容目录。全局搜索包含公开类型的文章正文和结构化字段。首页和搜索对话框共享对紧凑静态文档导出的全文匹配，不会分发大型倒排数据库。集合筛选在明确限定范围的结构化字段内使用相同的词元匹配规则。完整源注册表仅限服务端；客户端包不会导入研究台账。仅限客户端的表单控件会保持禁用，直到水合恢复浏览器查询状态；原生链接、展开详情和文章阅读在无 JavaScript 时仍可使用。这样可防止较早的选择被静态占位状态吞掉。

源 Markdown 始终是权威来源，文档准备过程绝不会改写它。经过审阅的原生 HTML，如展开详情、摘要文本、行内代码和显式锚点，都会保留。新的原始 HTML 标签或属性需要显式策略，而不是被静默丢弃或执行。

## 验证层次

1. **源清单：** 将注册键与原始集合及独立加载的片段导出进行比较。拒绝未分类模块、未处理字段、重复项、孤立附件、缺失署名及无效引用。
2. **静态路由清单：** 从注册表中的公开规范地址推导预渲染路径、站点地图条目和构建清单，而不是维护另一份页面列表。
3. **渲染覆盖：** 要求每条公开记录出现在其规范 HTML 页面或锚点上，具有真实的发现入口，并包含面向读者区块中的可见文本、链接、图片和录像来源。仅限源端的元数据保留在清单中。文章文本与链接会对照原始 Markdown 检查。
4. **新鲜度：** 比较来源及内容摘要，确保源更改后旧构建无法通过。
5. **回归测试：** 故意省略记录、片段行、字段、路由和媒体引用，以验证检查会失败。
6. **浏览器检查：** 测试筛选、客户端/模型署名、多录像选择、移动布局、直接 URL、全局搜索及无 JavaScript 阅读。

构建前运行 `npm run check`。运行 `PAGES_BASE_PATH=/GameMap/ npm run build`，然后运行 `npm run check:build`。用 `npm run preview` 打开页面，检查两个语言版本的筛选、跳转和移动端展示。源检查不要求已有构建目录。

构建会发布机器可读的 `content-manifest.json`，包含全部注册记录，包括仅供内部编写使用的路径和步骤。公开记录可通过所属集合和全局搜索发现。数量从当前源记录推导；本文不手动维护数量。这些检查验证内容可见性与内部一致性，并不证明执行情况、许可已获准、生产就绪性或外部项目事实已核实。

## 开发与包

`npm run dev` 从仓库的内容文件和翻译覆盖层生成派生产物，准备文档并启动 React Router 本地预览。

开发服务监听内容源、Markdown 和导航配置。刷新失败时会在终端报告错误。修正源数据后再次保存，让开发服务重新准备数据。

`npm run build` 从同一组源文件生成静态发布产物。`npm run preview` 读取已有构建，所以修改源数据后需要先重新构建。

目录数组与仓库研究台账共用 `data/segments/`，并在源清单中显式声明类型。研究台账不会被提升为资源卡片。技能包位于 `docs/skills/` 下，保留各自独立许可证，并生成确定性归档，逐字节对照源文件检查。

## 文档语言

英文 URL 保持不变。中文应用视图使用 `/zh/`；现有 `/docs/zh/` 指南保留原地址。语言链接保留集合筛选条件和详情锚点。匹配的文档 slug 会选择真正的中文指南；未翻译文章可在 `/zh/docs/` 下阅读，带中文导航、英文来源标签及英文文章正文。文档入口打开所选语言的学习首页，可从任务路线和主题目录进入正文。侧边栏优先使用已翻译的对应文档，不重复同一篇文章。

界面消息位于 `website/content/i18n/` 下。内容翻译是仅限服务端的覆盖层，以原始 `kind:id` 和源文本字段为键。它们不会创建资源记录，也不会改变 ID、枚举值、来源 URL、创作者署名或许可证。每个翻译字段都具有经审阅的英文来源指纹；源变更后会回退为英文，并使语言验证失败，直至审阅完成。关卡设计工具包视图从目录实体继承已翻译的标题和摘要。

两个语言版本的公开记录都会预渲染，并检查可见字段、所属集合、导航发现、Markdown 正文、语言感知的内部链接、来源语言标记及静态搜索。本地化摘要可防止翻译变更后陈旧构建通过检查。原生语言链接与阅读无需 JavaScript 即可使用。

## 添加内容

- 编辑 `data/segments/` 或 `website/src/data/` 下拥有该条目的文件，保留来源证据与限制。
- 在已有类型的集合里新增记录时，为新记录分配稳定标识。适配器将该记录纳入注册表。
- 对于新数据模块或导出，在源清单中声明其所有者与结构。片段还必须包含在其聚合集合中；独立清单检查会检测遗漏。
- 对于新字段或内容类型，在发布前定义其类型与显式展示方式。结构性省略需要解释；未知运行时字段会导致验证失败。在 `contracts.ts` 中声明运行时模式，推导 TypeScript 类型，并在 `contentKinds` 中声明版本、所有者和验证器键。
- 在 `docs/` 下任意位置添加 Markdown。导航、静态渲染、搜索及覆盖发现会自动跟进。可在 `website/docs.config.json` 中添加可选标签，以便有意安排位置。
- 不要仅为简化视图而移除不可用来源、历史身份、替代录像、署名边界或许可限定条件。
