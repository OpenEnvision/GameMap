# 搭一段灰盒，看别人怎么走

玩家走到锁住的出口，掉头，又从该进的走廊前经过。房间里哪条线索让他这么走？用几块基础几何体搭个小中继站，找没见过布局的人玩一遍，再根据他走过的路改一处。

沿用已有的步行控制器。请人试玩前，自己用实际的镜头、速度和碰撞走一遍。[《关卡设计之书》](https://book.leveldesignbook.com/process/blockout/playtesting)把自测和观察新玩家分开。自己走能发现门洞太窄，新玩家能告诉你那里看起来到底像不像一扇门。下文的尺寸和测试记录都服务于这道练习。

## 1. 写简报，画清空间连接

**玩家动词：** 移动、观察、交互。拾取电池只需设置携带状态，不要求制作背包界面。**目标：** 恢复出口插座供电并离开。**面向玩家：** 熟悉第一人称操作、但从未见过这个布局的人。

起点面向出口。空插座说明缺少一块中继电池。电池旁的条纹标杆通过廊道开口形成地标。返回通道需要从远端打开。

```text
            [B: CELL]--------[R: LATCH]
                |                :
           [C: GALLERY]           :
                |                :
[S: START]---[J: HUB]--------[G: SOCKET]---[E: EXIT]
```

实线表示可双向通行的连接，其中 G–E 需要电池才能解锁。虚线 R–G 通道初始关闭，玩家从 B 一侧操作 R 后才会打开。字母用于你的设计记录；玩家只会获得目标和交互反馈，不会看到这张图。

预期顺序是 S–J–G、J–C–B，再走 B–R–G–E。沿 B–C–J–G 原路返回也必须可行。所有空间保持在同一层，避免楼层辨认干扰导航问题。

## 2. 搭建灰盒

1. 在一条测试带中，用实际相机检查步行、转向、碰撞和交互。记录控制器版本、速度、视野角度及输入设备。
2. 可从约 18 × 12 m 的占地、2 m 宽的通道和 1.4 m 宽的门洞开始。这些都是可修改的起点。控制器无法舒适通过或转身的地方应加宽。
3. 让 S 经过 J 到 G 的距离约为 8 m。搭建 J–C–B，再连接 B–R–G。添加装饰前，先把每条连接正反走一遍。
4. 把条纹标杆放在 B，用玩家眼睛高度从 J 检查它是否可见。除明暗对比外，同时使用轮廓和条纹，不只依赖颜色。
5. 加入电池、插座和门闩状态。安装电池后打开 E。R 只能从 B 一侧打开，且在本轮游玩中保持开启。
6. 重置会让玩家回到 S、电池恢复到 B、两道门关闭。阻止玩家离开灰盒边界。对比测试期间保持这些规则不变。

## 3. 先写下预测

**假设：** 不熟悉布局的玩家发现空插座后，无需路线提示，就能辨认廊道路线、取得电池并返回出口。

| 问题                   | 记录内容                         | 什么现象会挑战预测？                   |
| ---------------------- | -------------------------------- | -------------------------------------- |
| 廊道看起来能通行吗？   | 到过 G 后，从 J 选择的第一条路线 | 反复回到 G，却不进入 C                 |
| 捷径表达了返回关系吗？ | 取得 B 后的路线；在 R 的尝试     | 玩家忽略 R，或把它当成另一个锁住的出口 |
| 尺寸适合控制器吗？     | 卡顿、交互失败及相机遮挡         | 碰撞或交互距离阻止了导航行动           |

可安排三名不熟悉布局的测试者，每人观察 180 秒。暂以两人无需协助完成为目标；任何软锁都会阻止验收。这是针对极小样本的修改触发条件，不是对整体玩家成功率的主张。若要修改预测，请留下变更记录，不要在看到结果后改写原预测。

## 4. 提供反馈和恢复方式

| 情况         | 即时反馈                         | 恢复方式                             |
| ------------ | -------------------------------- | ------------------------------------ |
| G 没有电池   | 形状匹配的空插座；“需要中继电池” | 转身回到 J                           |
| 玩家拾取 B   | 电池消失；确认携带状态           | 电池不能被丢到无法到达的位置         |
| 玩家接近 R   | 从 B 一侧能看到并操作门闩        | B–C–J 仍是一条可选的返回路线         |
| 玩家安装电池 | 插座状态改变，E 明确打开         | 重复交互不会再次消耗电池或重新锁住 E |

检查忘记拿电池、提前到访 R、沿长路线原路返回，以及完成后重置的情况。走错路后，玩家仍应有一个有用的后续行动。

## 5. 做盲测，填写记录表

只提供操作说明和“恢复中继站供电并离开”的目标。每位测试者都从同一状态开始。安静观察，不要指向 C 或解释标杆。如果必须协助，记录协助发生的时间和内容，并把此后部分归为受协助的游玩。完成或达到时限后停止；超时也是有效结果。

记录构建版本、控制器设置及玩家相关经验。录制前取得同意。将观察到的动作与你的解释分开记录。

| 测试者／构建版本 | 路线与决策 | 到达 G、B、R、E 的时间 | 协助／结果 | 具体观察 |
| ---------------- | ---------- | ---------------------- | ---------- | -------- |
| ___ / ___        | ___        | ___                    | ___        | ___      |
| ___ / ___        | ___        | ___                    | ___        | ___      |
| ___ / ___        | ___        | ___                    | ___        | ___      |

结束后再问：“你以为目标是什么？”“哪些开口看起来可以通过？”“你觉得门闩会做什么？”如果没有不熟悉布局的人实际试玩，把记录标为**仅自行走查**，玩家结果保持空白。

## 6. 从一项观察得到一次修改

**说明性示例，并非实测结果：** 一名测试者两次到达 G，在 J 停下，却从未进入 C。之后他说，开口看起来像墙上的凹槽。

- **待验证的诊断：** 开口轮廓让其用途不明确。另一种解释是插座文字没让玩家理解寻找电池的目标。
- **下一版本：** 保持目标、速度和路线长度不变；只挪开挡住 C 的那根柱子，保留原来的地面和灯光。
- **复测：** 请另一名不熟悉布局的测试者完成相同任务。记录他是否进入 C；仅凭完成得更快，无法证明解释正确。

避免同时加上箭头、小地图和更亮的奖励。保留改动记录，每次修改后重做反向通行和重置检查。

## 7. 判断哪些部分已经就绪

| 验收项目                                     | 证据／结果 | 决定               |
| -------------------------------------------- | ---------- | ------------------ |
| 两条返回路线均可用；重置能恢复全部状态       | ___        | 通过／修改／未测试 |
| 没有无法取得的电池、卡住的门或阻断通行的碰撞 | ___        | 通过／修改／未测试 |
| 已检查盲测条件，未隐去协助或超时             | ___        | 通过／修改／未测试 |
| 一项优先修改有对应观察及另一种解释           | ___        | 通过／修改／未测试 |

在能说明剩余不确定性之前，保持灰盒易于修改。随后再据此决定是否进入美术制作。

## 在三份模板中跟踪同一个设计决策

以下填写内容展示三份记录怎样衔接。它们是中继站练习的填写示例，没有实际参与者的观察结果。

| 模板 | 填写示例 |
| --- | --- |
| 关卡简报 | 初次试玩者看到空插槽后，在枢纽应能辨认出走廊可以通行。记录从枢纽第一次转向。保持控制器和目标固定。 |
| 试玩报告 | 第一次返回枢纽时，记录时间、选择的开口、玩家原话和是否得到提示。测试前留空观察与结果栏。 |
| 评审 | 如果玩家反复经过走廊却说它看起来像壁龛，在下一构建中验证开口轮廓。保留旧构建，用新玩家观察同一个决策点。 |

搭建关卡的代理可以交付场景和指定验收路线。游玩代理可以在固定接口和预算下验证可达性、门闩状态或重置行为。让第一次接触关卡的玩家判断开口是否像可通行路线、目标是否清楚。分别保留三种记录，并标明各自的测试主体。参见[开发评估](../evaluation/development-evaluation.md)。
