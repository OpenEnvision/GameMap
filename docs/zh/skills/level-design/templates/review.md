## 发现

对每个实质问题重复以下内容。

### ［优先级］简短问题陈述

**问题：** 什么阻碍或削弱了预期体验？

**具体追溯：** 在哪里、何时、什么状态下？评审者观察到了什么？区分观察与推断。

**示例／复现：** 他人能够遵循的一段简短步骤。

**最小有效改动：** 具体干预及其改变的关系。

**必要性：** 解释它针对什么失效。区分必需修正与可选打磨。

**取舍：** 什么可能变差或成本更高？

**验证：** 谁应在什么条件下做什么，以及什么证据能支持改动？

**信心／限制：** 直接观察／有支持的推断／未经测试的假设。

## 评审视角

仅使用相关视角：

- 意图、范围与推进。
- 移动、镜头、尺度与碰撞。
- 流线、垂直性、门槛与重试。
- 战斗职责、信息、掩体与资源。
- 多人时机、控制与恢复。
- 寻路引导与习得的视觉惯例。
- 脚本状态、中断与持久化。
- 照明、材质、故事与可读性。
- 性能与流式加载。
- 打包、依赖、署名与访问。
- 文化情境与预期社会用途。

## 问题示例：入口看起来像凹槽

这份 GameMap 示例衔接[试玩测试报告](playtest-report.md)中假设的 `relay_v01/P01` 记录。它展示如何提出改动请求，不是实际测试发现。

| 问题字段     | 示例填写                                                                                                                            |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| 优先级       | 下一轮调查。尚未证明它会阻止推进。                                                                                                  |
| 问题         | 从 J 看过去，C 入口可能不像可通行的延续路线。                                                                                       |
| 具体轨迹     | 在示例场次中，玩家两次到达 G，都没有进入 C。未记录玩家对原因的解释。                                                                |
| 复现／检查   | 打开指定构建，到过 G 后在未携带电池的状态下回到 J。从实际玩家镜头查看 C，再走过去。这会检查几何与视点，不能替代陌生玩家的理解测试。 |
| 最小有效改动 | 让可行走地面的处理延伸穿过 C 开口。保持控制器设置、通道尺寸、插座文字及全部门槛规则不变。                                           |
| 代价         | 更强的路线强调可能削弱探索所需的不确定感；地面修改也可能影响其他位置的材质对比。                                                    |
| 验证         | 用相同目标和初始状态，请新玩家测试修改后的构建。记录到过 G 后首先选择的路线。同时走过长返程路线与捷径，并重置电池／门槛。           |
| 置信度／限制 | 入口可读性仍是假设。另一个解释——寻找电池的目标不明确——尚未排除。                                                                    |

根据后果与证据分配优先级。可复现的门槛软锁必须在交付前修正；单次犹豫通常需要继续调查。在应保留的优点中写明有效关系，只请求改动所选干预涉及的文件或场景物体。
