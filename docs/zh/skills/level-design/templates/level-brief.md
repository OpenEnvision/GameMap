## 首轮示例：一条返回路线

先填写标识、意图、核心活动与推进、首个原型，以及试玩测试与下一项决策，再扩展其余部分。其他章节用于记录会影响当前片段的决定。某个字段可以写“未知；到控制器场景中检查”，不要把假设藏起来。

这份规划示例属于 GameMap 改编，不代表已完成的关卡或玩家结果报告。以下标识描述一个复用步行控制器和交互动作的小型第一人称关卡。

| 简报字段         | 示例填写                                                                                                          |
| ---------------- | ----------------------------------------------------------------------------------------------------------------- |
| 关卡／版本       | `relay_v01`；拟搭建的白盒；尚未进行试玩测试                                                                       |
| 体验目标         | 先看到目的地，找到其缺失电池，并认出较短的返回路线。                                                              |
| 核心推进         | 从 S 出发，查看插座 G，经 J–C–B 取得电池，返回 G，再从 E 离开。B–R–G 是可选捷径；B–C–J–G 仍可通行。               |
| 状态与重置       | 开局未携带电池，捷径关闭。插入电池后解锁 E。本轮中打开 R 后保持开启。重置会恢复电池并关闭两道门。                 |
| 固定／暂定       | 保持现有控制器、镜头和输入不变。通道尺寸和入口处理暂定。                                                          |
| 非目标           | 当前片段不做战斗、背包界面、垂直移动或最终环境美术。                                                              |
| 风险最高的假设   | 陌生玩家查看 G 后，能把 C 识别为路线，而不是墙上的凹槽。                                                          |
| 最小原型         | 一个岔路口、可见插座、廊道入口、电池，以及可用的返回通路。                                                        |
| 测试与下一项决策 | 记录玩家到过 G 后在 J 首先选择的路线、协助及最终结果。如果玩家反复返回 G 而不进入 C，分别检查开口表达和目标信息。 |

交给实现者之前，将示例标识替换为实际场景／物体名称，附上连接图，并明确由谁执行测试。在[试玩测试报告](playtest-report.md)中链接对应场次，把下一项改动写入[评审](review.md)，保留这个版本原来的预测。
