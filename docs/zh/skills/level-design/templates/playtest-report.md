## 把一次测试完整填入表格

测试前，从[简报](level-brief.md)复制问题和预测，分配场次 ID，并保存这份计划。游玩期间在决策点记下短笔记，结束后对照录像补充，并标明近似时间。原始录像或笔记使用同一场次 ID 保存。

下面是 `relay_v01/P01` 的假设性填写示例，不是采集到的数据。问题是：陌生玩家查看插座 G 后，是否会进入廊道 C。

| 时间／位置／状态        | 观察到的行为                                | 玩家陈述     | 协助／干预             |
| ----------------------- | ------------------------------------------- | ------------ | ---------------------- |
| 约 00:30；J；未携带电池 | 在 J 停下，转向 G，随后返回 G，没有进入 C。 | 未记录陈述。 | 此示例序列中没有协助。 |
| 约 00:55；G；未携带电池 | 再次查看插座，然后返回 J。                  | 未记录陈述。 | 此示例序列中没有协助。 |

这些记录可以支持继续追问为什么错过 C，但不能证明玩家感到无聊、路线无法完成，或任务最终失败。在结果部分另行记录完成、超时、受到协助或因技术故障停止。一个可能的解释是 C 看起来像凹槽；另一种解释是插座没有传达寻找电池的目标。[评审](review.md)会把这个尚未确定的问题转为一项建议改动和新的测试。

真实报告应将示例替换为实际事件。保留每一场计划内测试，包括未完成及受到协助的尝试。如果参与者是游玩代理，在测试标识中补充模型／客户端版本、观察与动作接口、重置／种子，以及动作／时间预算；逐局记录终止原因。这些运行与人类路线理解测试分开保存。
