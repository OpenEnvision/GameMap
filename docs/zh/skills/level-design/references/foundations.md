# 基础、前期制作、研究、世界构建与范围

来源：[什么是关卡设计](https://book.leveldesignbook.com/introduction)、[如何制作关卡](https://book.leveldesignbook.com/process/overview)、[前期制作](https://book.leveldesignbook.com/process/preproduction)、[节奏](https://book.leveldesignbook.com/process/preproduction/pacing)、[研究](https://book.leveldesignbook.com/process/preproduction/research)、[世界构建](https://book.leveldesignbook.com/process/preproduction/worldbuilding)、[范围](https://book.leveldesignbook.com/process/preproduction/scope)。依据 CC BY-NC-SA 4.0 改编与重组。

## 1. 确定正在设计什么

关卡设计将活动和空间与机制、美术、代码、叙事、声音及玩家的文化知识联系起来。系统确定可能的行动；关卡将这些行动置于具体情境中。这些职责相互交叠，尤其是在小团队中。

不要将这一领域局限于射击游戏的房间与走廊。类型、工具、制作历史和分工都会改变“关卡”的含义，以及设计者能够控制的内容。

有效的流程可以从一个有趣情境出发，直接进入原型制作，发现缺少某项机制，再回到研究阶段。前期制作是为了减少代价高昂的不确定性，而不是禁止动手制作。

## 2. 最简前期制作

回答：

- 玩家目前知道什么、拥有什么、会做什么？
- 他们在这里应该做什么、理解什么，或感受到什么？
- 哪种可玩的空间关系能够表达这一意图？
- 游玩如何开始、结束、失败和重新开始？
- 哪些约束是固定的，哪些是需要测试的假设？

设计支柱必须能够支撑决策。“宏大、刺激、沉浸”无法判断一条分支是否必要。“在反复改变高度的同时，让远处目的地始终可辨认”则可以指导路线、地标和镜头视野。

文档写到足以协调下一步即可。必要时添加负责人、依赖和验收标准；简短的个人练习不需要庞大的设计文档。

### 从体验目标到下一次构建

这份已填写的简报是面向小型第一人称中继站的改编示例。它规定接下来要开展的测试，不是已经取得的结果。

| 决策             | 工作简报                                                   |
| ---------------- | ---------------------------------------------------------- |
| 已有能力         | 行走、观察和使用物件；复用项目当前的控制器                 |
| 玩家处境         | 到达未通电的出口，在侧廊找到电池，再返回                   |
| 体验目标         | 通过侧廊解决供电问题，并记住返回的目的地                   |
| 空间方案         | 廊道通向电池；附近的门闩打开返回出口的捷径                 |
| 下一构建保持不变 | 控制器、目标文字、电池交互和起点                           |
| 不确定项         | 从交汇处看，廊道入口是否像可通行的开口                     |
| 下一构建         | 用低成本几何搭出交汇处、出口插座、廊道入口、电池和返回门闩 |
| 要收集的证据     | 看到空插座后首次选择的路线、交互尝试、协助，以及完成或超时 |

关卡设计者负责连接和第一视图；玩法程序员负责电池与门闩状态。若由同一个人或代理同时完成，仍应在简报中区分这两种职责。交互缺失应先修复，再判断失败是否来自寻路理解。

明确范围删减：保留侧路与返回关系，用静态电池物件替代定制动画，暂缓移动列车和语音播报。列车会引入时序、碰撞、动画和音频工作，却不能回答当前问题。首次走查后，决定修改入口还是进入陌生玩家测试；默认的下一步不是增加房间。

## 3. 研究关系，而非漂亮的表象

### 现实世界参考

收集平面图、结构、尺寸、材料、流线、用途及使用痕迹。照片常常隐藏场所之间的连接方式；应补充平面图或多个视角。

以车站为例，询问：

- 谁会到达、换乘、工作、补给和疏散？
- 公共区、员工区、服务区与危险区如何分隔？
- 哪些部分可成为地标、俯瞰点、瓶颈、环路或替代进路？
- 哪些现实限制需要为游戏作调整？

### 游戏参考

条件允许时，亲自游玩、绘图、记录并检查关卡。视频能提示关系，却无法确定操控手感、探索负担或战斗压力。

区分：

1. **观察：** 敌人占据桥梁；侧路返回入口。
2. **解读：** 敌人可能吸引注意；返回可能强化空间记忆。
3. **支撑规则：** 镜头、速度、伤害、重生、感知和资源。
4. **迁移测试：** 使用目标游戏的实际机制重建这种关系。

用情绪板统一氛围与视觉意图，用拆解说明组成部分与功能。二者不能互相替代。

## 4. 节奏：活动、顺序与变化

**节拍** 是活动或事件的一个有效单位，不一定是一个房间。战斗、观察、移动、谜题、补给、期待与宁静都可以是节拍。

先定义活动，再分配尺寸和时长。大空间未必激烈，小走廊也可能极其紧张。

### 低成本表达方式

- **节拍表：** 顺序、活动、玩家知识、资源、强度、过渡与测试问题。
- **流程图：** 分支、条件、循环和可跳过事件。
- **强度图：** 表达预期节律，而非实测玩家情绪。

**重点场面** 围绕一个鲜明事件协调多个专业。投入昂贵奇观之前，应明确脚本、美术、动画、音频、镜头和性能依赖。

### 有用的模式，而非硬性要求

- 先收集值得保留的节拍；顺序可以通过编排与测试逐渐形成。
- **教学—考验—变奏：** 清晰地引入一种关系，检验理解，再改变条件。变奏不只是增加敌人或生命值。
- 交替提出不同要求，留出恢复、理解和期待的空间。持续最高强度可能造成疲劳，而非层层递进。
- 高潮可以解答情感、主题或概念上的问题，不一定是数值上最难的一战。

### 非线性与多人节奏

玩家可能以不同顺序遭遇节拍。应使用局部序列、可重复模式、资源循环、变化的目标和玩家生成的事件，而不是依赖一条必然发生的曲线。

开放世界节奏应包含行进、发现、中断和可选绕行。不要仅为维护一张图表而剥夺自主性。

### 何时不该“修正节奏”

节奏是一种分析视角，而非普适的戏剧公式。漫游、别扭、中断、静止或拒绝高潮，都可能是有意为之。提出常规升级方案之前，先明确作品的目的。

## 5. 支撑空间的世界构建

**问题：** 丰富的背景设定未必能产生可玩的关系。

**示例：** 一座城堡拥有详尽的王室谱系，却没有合理的守卫流线、补给路线、服务入口，也没有可攀爬城墙存在的理由。

**应对：** 从谁使用这里、他们做什么、发生了什么变化开始，再看这些事实如何转化为路线、物件、可供行动的条件与线索。

- **最简世界构建：** 地点、居民、日常活动、冲突与近期事件。
- **全面世界构建：** 在项目需要时提供地理／气候图、政治地图、时间线和有组织的笔记。
- 优先考虑玩家能够观察、推断或据以行动的关系，而不是百科条目。
- 随着机制、白盒、试玩测试和美术的发展，为修改虚构设定留出余地。
- 世界可以通过反复出现的空间与视觉关系表达思想；说明性叙述不是唯一渠道。

## 6. 估算制作成本，而不只是面积

计入：

- 空间与移动。
- 独有机制、敌人、脚本与交互。
- 资源、表演、音频、照明与优化。
- 测试、返工、打包与展示。

**垂直切片** 让有代表性的一部分内容经过必要的各制作专业环节。它揭示依赖与成本；它并不天然等同于第一个灰盒，也不保证成本可以线性外推。

区分：

- **必须保留：** 能够表达核心关系的最小版本。
- **可替换：** 能够使用现有系统或资源的内容。
- **可选／可删：** 成本高却不支持目标的新奇内容。

应先删去代价高昂、理由薄弱的功能，而不是平均削弱整个关卡。

## 建议交付物

一页简报、成本最低且有用的结构表达、一个高风险假设，以及下一次试玩测试的问题。当文档能够改善具体决策或协调问题时，再增加文档。
