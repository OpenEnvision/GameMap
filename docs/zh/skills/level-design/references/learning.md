# 学习、教学、练习、评议与作品集

来源：[教育者笔记](https://book.leveldesignbook.com/learning/notes)、[项目计划](https://book.leveldesignbook.com/learning/projects)、[经典战斗](https://book.leveldesignbook.com/learning/projects/classic-combat)、[未完成的在制项目](https://book.leveldesignbook.com/learning/projects/unfinished-wip-pages)，以及下文列出的关联练习。依据 CC BY-NC-SA 4.0 改编与重组。

## 1. 教授完整的小型迭代

有用的学习循环是：

**研究 → 提案 → 沟通 → 搭建 → 观察 → 修改 → 反思。**

一个经过多轮证据驱动修改的小型可玩关卡，通常比大型静态环境更有助于学习关卡设计。

区分：

- 理论与分析词汇。
- 技术搭建与工具操作。
- 可玩设计决策。
- 沟通与评议。
- 对过程的反思。

原书提供理论与练习，而不是面向每种引擎的完整技术课程。教师必须补充缺失的工具教学。

## 2. 根据学习目标选择工具

- 对聚焦遭遇与空间设计的学习，Doom 或 Quake 提供现成的移动、战斗、敌人及成熟制图社区。
- 对通才开发或不同种类的体验，Unity、Unreal、Godot 或其他适当工具可能更合适。
- 计入构建缺失机制所需的时间。否则“关卡设计课”会变成“控制器编程课”。
- 共享的初始工具集有助于全班建立共同示例和术语。在基础与支持结构建立后，再允许专业化选择。

不要将这些选择理解为对工具正当性的普适等级划分。

## 3. 简短的学习进程

这是改编的顺序，不是来源官方规定的固定课程。

| 阶段 | 主要任务            | 证据             |
| -- | --------------- | -------------- |
| 观察 | 游玩并标注一个现有小关卡    | 少量具体的行动—空间关系   |
| 沟通 | 为一场遭遇或一条路线绘图并提案 | 他人能解释其意图与选项    |
| 搭建 | 用现有机制使其可玩       | 可从头玩到尾的白盒      |
| 测试 | 观察不熟悉关卡的玩家      | 定位明确的观察，而不只是意见 |
| 修改 | 改变一项有证据支持的关系    | 修改前后证据         |
| 完成 | 打包并编写文档         | 他人能够安装并理解      |
| 反思 | 比较意图、过程与结果      | 明确的下一项学习目标     |

当学习工具耗尽日程时，应缩减范围。不要为保留装饰野心而取消测试。

## 4. 经典战斗：最完善的项目计划

[经典战斗](https://book.leveldesignbook.com/learning/projects/classic-combat)要求学习者研究、提案并制作一个 Doom／Quake 风格小型竞技场原型。

### 来源特定的简报

- 一个房间。
- 两到三种怪物。
- 一到两种武器。
- 约一到两分钟游玩。

这些约束属于本练习，而非战斗设计的一般规定。

### 工作流程

1. 充分游玩所选游戏，能够识别武器、怪物、移动与交互。
2. 阅读相关评论，并讨论其论点依赖什么。
3. 快速制作多张组织示意图和备选布局。
4. 选择其中一个，作实质性修改，并标注起点、敌人、物品、危险与推进流程。
5. 提案说明预期体验，以及数种合理的玩家策略。
6. 核查游戏特定度量，搭建一个小型可玩竞技场。
7. 先自测，再请他人测试。
8. 同时改变一项空间关系与一项敌人／物品关系。
9. 考虑一个发现方式契合关卡的秘密。
10. 反思研究、沟通、搭建、测试与修改。

来源建议至少三位外部测试者，以及短期制作时限。这些是实用练习目标，并非统计上充分的样本或通用日程。

### 评估

- 体验目标是否连贯且鲜明？
- 是否真正支持多种策略？
- 他人能否理解方案？
- 度量与敌人行为是否支持预期遭遇？
- 观察是否促成了有意义的修改？
- 学习者发现了自身流程的什么特点？

不要将练习建议的死亡次数或完成时间变成普适质量指标。

## 5. 其他项目：保留其草稿状态

### 现代战斗——未完成

[来源](https://book.leveldesignbook.com/learning/projects/unfinished-wip-pages/modern-combat)。

研究现代掩体／动作战斗，考察预设与系统性 AI，绘制包含节拍、掩体、视线和区域的小型遭遇，再作提案。

来源 **没有** 解决工具／原型配置问题。布置实现任务前，应提供具有合适战斗与 AI 的游戏或项目。不要承诺通用引擎模板已经支持它。

### 现代潜行——未完成

[来源](https://book.leveldesignbook.com/learning/projects/unfinished-wip-pages/modern-stealth)。

草稿聚焦于观察潜行遭遇，以及研究 Splinter Cell: Blacklist 中的感知／警觉。它不包含完整的搭建与评估作业。

改编：若要扩展，应明确提供机制，并测试可读的怀疑、搜索、恢复与转入战斗的后备流程。将这些新增内容标为你自己的作业设计。

### 直接照明——短练习

[来源](https://book.leveldesignbook.com/learning/projects/unfinished-wip-pages/exercise-direct-lighting)。

使用手动放置的直射光与补光／反弹光，为简单白盒布光。禁用与练习相关的自动／预计算辅助。若色彩遮蔽了教学重点，从灰度表面与低饱和度光开始。

这是帮助理解光的学习约束，不是主张制作中应避免现代照明系统。

### 白板 2D——提纲

[来源](https://book.leveldesignbook.com/learning/projects/unfinished-wip-pages/exercise-whiteboard-2d)。

绘制带收集物的平台游戏布局，并在重要情境中标出玩家屏幕范围。展示哪些内容可见，以及收集物如何影响移动。链接阅读是额外作业，不是页面中已经包含的内容。

### 改编——简短任务说明

[来源](https://book.leveldesignbook.com/learning/projects/unfinished-wip-pages/adaptation)。

将现实场所改编为单人关卡，考察类型学、体块、玩法适配与范围。解释哪些被简化、保留和改变。

### 布局——提纲

[来源](https://book.leveldesignbook.com/learning/projects/unfinished-wip-pages/exercise-floorplan)。

草稿提出一个关于解锁门并离开的短关卡，通过目标、节拍、研究、空间构思图、气泡图和布局，比较更好／更差的组织方式。

改编：要求学习者解释可玩后果上的某项具体差异，而不只是把一张图标成“差”。

### 垂直性——短练习

[来源](https://book.leveldesignbook.com/learning/projects/unfinished-wip-pages/verticality)。

抽象表达主要高程，省略细小高度噪声，为过渡和落脚点预留空间，并在有用时分开绘制重叠楼层。画出能传达核心关系的内容，而非制作不必要的建筑细节。

## 6. 更长的课程结构

来源给出一个示例学期：

- 简短前期制作。
- 反复进行布局沟通与修改。
- 大量白盒与脚本时间。
- 依据学生群体目标安排制作重心。
- 展示与反思。

根据工具熟悉程度、课时、无障碍需求和项目范围调整日历。初学者还没有足够的搭建与游玩经验来理解抽象规划时，不要先布置大量此类任务。

将讨论与共同游玩或观察配对。将文化与案例研究章节用于辩论，而不只是当作权威答案。

## 7. 开展有用的评议

评议从简短说明意图与方法开始。随后：

- 描述一个值得保留的具体优点。
- 描述一个削弱它的具体问题。
- 使用第一人称、定位明确的观察。
- 提问以暴露假设。
- 提供备选方案，不把品味当作事实。
- 以可处理的下一次实验结束。

“返回庭院后，我认不出出口”比“谁都不知道该往哪走”更有用。

快速 **贴图评议** 可以使用短提示、速写、小组展示与聚焦讨论。目标是思路更清晰、方向得以更新，而不是羞辱。

## 8. 作品集：草稿来源，有用原则

[关卡设计作品集](https://book.leveldesignbook.com/learning/projects/unfinished-wip-pages/level-design-portfolio)是非正式提纲，不是定论性的招聘标准。

实用改编：

- 说明目标岗位，并立即展示相关作品。
- 保持导航与文字简洁。
- 展示代表性游玩、带标注布局、迭代和个人贡献。
- 提供可用链接，并在移动端测试。
- 署名合作者与外部资源。
- 避免公开不必要的个人信息。
- 保持作品集与可下载简历最新。

草稿中关于特定托管服务和社交平台的意见具有时效性。使用能让作品方便访问的当下工具，而非照搬旧平台规定。

## 交付物

学习计划应明确目标、前置条件、工具、时限、小型成果、反馈方法、修改要求与反思问题。标明来源练习在哪里结束，你的新增内容从哪里开始。
