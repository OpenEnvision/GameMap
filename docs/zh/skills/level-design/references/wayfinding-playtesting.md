# 寻路引导、玩家理解与试玩测试

来源：[寻路引导](https://book.leveldesignbook.com/process/blockout/wayfinding)、[试玩测试](https://book.leveldesignbook.com/process/blockout/playtesting)、[玩家画像](https://book.leveldesignbook.com/process/blockout/playtesting/persona)。依据 CC BY-NC-SA 4.0 改编与重组。玩家画像页面简短且未完成；此处的操作检查清单属于改编。

## 1. 区分导航问题

玩家可能：

- 无法察觉出口。
- 无法将可见出口理解为可用通道。
- 不确定目标。
- 不确定某项机制如何运作。
- 记不住来路或当前楼层。
- 正在有意探索。
- 自信地追寻一个非预期却合理的假设。

这些情况需要不同的干预。“他们迷路了”是症状，不是诊断。

**寻路引导** 关注玩家如何建立并使用对环境的理解。它不同于 AI 寻路，后者计算或沿着可通行路线行动。

## 2. 支持可用的心智地图

有用的环境类别包括路径、边界／边缘、鲜明的区域、重要节点和地标。其价值来自实际玩家的体验，而不是把每一类别逐项打勾。

- 让重要地点在相关距离上可以区分。
- 让反复出现的视觉惯例保持足够一致，以便学习。
- 让路线揭示先前彼此分离地点之间的关系。
- 利用横跨空间或回望空间的视野确认位置。
- 考虑从每个相关入口进入及重生后的定向。

地标必须可注意、可区分，并有助于定向。若一座大雕塑在每个决策点都藏在玩家背后，它并不会自动成为有效地标。

## 3. 引导是多层次的假设

可能的线索：

- 地面连续性、开口、门限与流线。
- 框景、对比、明度、照明、轮廓与运动。
- 可辨认的物件与活动。
- 目标、敌人、奖励、资源轨迹与好奇心。
- 声音、对话、标识、界面与明确标记。

应优先使用一组连贯线索，而不是多个相互竞争的吸引物。不要假定亮光总能吸引注意、某种颜色总代表安全，或玩家必然看向截图构图所指之处。

来源讨论了确定性层级与引导的局限。应将其中的百分比或非正式规则视为设计启发，而非经过验证的普适概率。

### 决策点审查

对每个有实质影响的选择，记录：

1. 玩家当前想要什么。
2. 他们从实际视野能察觉什么。
3. 哪些选项看起来可以行动。
4. 什么区分了这些选项的成本或含义。
5. 哪种反馈确认进展或错误。
6. 如果理解有误，他们如何恢复。

### 探索与清晰度

不要自动消除不确定性。应询问：

- 搜寻是否就是预期活动？
- 玩家是否有足够信息形成并修正假设？
- 走错路是否有趣、能提供信息或可以挽回？
- 判断错误的成本是否合适？
- 不确定性来自世界，还是仅来自晦涩的交互惯例？

发现可以是间接的，而不必是任意的。

## 4. 围绕问题规划试玩测试

试玩测试是他人游玩、设计者调查设计是否有效的过程。自测是必要的，却不能替代不熟悉关卡的玩家。

示例：

- 不熟悉关卡的玩家能否在开启捷径后，找出下一条可用路线？
- 远程敌人是否促使玩家换位，而非无限等待？
- 玩家掉到下层后能否恢复？
- 之前测过的路线在美术制作后是否仍清晰可读？

定义预期的可观察行为，以及会对假设构成挑战的结果。只问“好玩吗？”对于诊断性测试过于宽泛。

### 让方法匹配问题

- 安静观察可以保留自然行为，但意图仍不确定。
- 边玩边说可以揭示理解，同时也会改变注意力与节奏。
- 自由游玩能暴露意外行为。
- 聚焦任务可隔离某种特定关系。
- 埋点和录像有助于定位事件，但解读仍需要情境。

有意识地选择。不要在每次测试中混用所有方法，也不要将一次带埋点的运行视为对所有玩家的无偏呈现。

### 可交给测试主持者的会话计划

为[布局状态示例](spatial-layout.md)中的中继站招募任何人之前，先使用以下改编计划。样本量和时限是小型诊断测试的起始选择。

| 会话字段     | 已填写计划                                                        |
| ------------ | ----------------------------------------------------------------- |
| 问题         | 发现空插座后，初次试玩者能否将廊道辨认为可用路线？                |
| 构建与重置   | 固定一个构建及控制器配置；从 S 开始，电池在 B，捷径关闭           |
| 参与者       | 三名熟悉操作、但不熟悉此布局的人；记录相关经验                    |
| 说明         | 提供操作方式和“恢复供电并离开”；不指出廊道，也不展示路线图        |
| 停止规则     | 到达出口、经过 180 秒、参与者要求停止，或阻断性缺陷使测试无法继续 |
| 记录         | 到访插座后在交汇处首次转向；路线、交互尝试、时间、提示及最终状态  |
| 解读触发条件 | 反复返回空插座却不尝试廊道时，应调查其可读性                      |

每名参与者都保留一行记录，包括超时和出错的运行。将结果分为无协助完成、受协助完成、超时、阻断性缺陷和退出。若测试者请求帮助，记录提示原文，并在该处将轨迹分段。不要悄悄重启计时，只保留成功的那次尝试。

即使捷径已经开启，经廊道长路返回仍可能是有效选择。结束后询问玩家认为门闩有什么作用；没有使用它，本身不证明玩家漏看了它。自动代理到达出口验证的是另一项主张：记录其观察接口和预算，并将该运行与人类寻路理解的证据分开。

## 5. 招募与准备

- 选择与目标受众和当前问题相关的测试者。
- 涉及上手与定向的问题应包含不熟悉关卡的玩家。
- 测试高级移动或竞技关系时，使用熟练玩家。
- 记录相关过往经验，不要假定一个标签就能解释行为。
- 准备已知构建版本、操作方式、初始状态、重置方法与观察工具。
- 录制或收集可识别身份的信息之前，取得许可。

**玩家画像** 是对受众及其条件的暂定模型，不是现实玩家必然如此行为的证据。只有在影响决策时，才纳入技能、熟悉程度、目标、约束与无障碍需求。用实际证据更新假设。

## 6. 主持测试，避免污染结果

给予真实玩家本来会收到的信息。避免讲解预设路线、指出漏看的物件、道歉或为选择辩护。

如果必须干预：

- 记录确切时间与原因。
- 区分帮助前后的行为。
- 不要将受帮助后的结果计为无帮助成功。

若采用边玩边说，使用中性提示而非诱导性问题。安全、无障碍和参与者舒适度优先于维持测试条件。

## 7. 先收集观察，再作解释

使用分开的字段：

- **观察：** 行动、位置、时间、状态、重复尝试。
- **玩家陈述：** 参与者实际说了什么。
- **解读：** 提出的解释。
- **信心／替代解释：** 还有什么能解释该现象。
- **下一次测试：** 如何区分相互竞争的解释。

**说明性笔记，非实际测试会话**

- 观察：玩家两次穿过庭院，却从未进入楼梯开口。
- 陈述：“那看起来像墙面细节。”
- 解读：入口轮廓可能没有被识别为通道。
- 替代解释：目标可能把注意力引向了别处。
- 测试：只改变开口的可读性，再请一位不熟悉关卡的测试者测试。

不要把“我迷路了”直接转化为“加一张小地图”。

## 8. 测后访谈与解读

先问开放式问题：

- 你认为自己的目标是什么？
- 你认为可以去哪里？
- 你预期那个物件或那条路线会做什么？
- 你的理解在哪里发生了变化？
- 什么让你觉得困难，当时你想做什么？

玩家建议能揭示需求，却不自动等于最佳实现。协调陈述与行为，不要否定其中任何一方。

依据后果、可复现性、与目标的相关性及证据，排列问题优先级。先修复推进受阻、状态损坏和误导性的核心规则，再处理外观偏好。

## 9. 修改并复测

优先选择能测试解释的最小改动。记录各构建版本之间的差异。

证据不确定时，避免同时改变路线结构、照明、奖励、标识与敌人行为；否则难以识别原因。底层前提失效时，大幅重设计是合适的——只是不要声称它隔离了单个变量。

复测：

- 原始情境。
- 替代进路与反向通行。
- 重试与持久化状态。
- 与战斗、美术和性能的交互。

## 报告标准

使用[试玩测试报告模板](../templates/playtest-report.md)。说明样本限制，并明确结论属于观察、有证据支持的解释，还是未经测试的假设。

如果没有开展试玩测试，应提供计划，并将发现标为 **专家走查** 或 **假设** ，绝不能写成“玩家做了什么”。
