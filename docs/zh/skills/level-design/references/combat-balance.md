# 战斗、敌人职责、遭遇、掩体与地图平衡

来源：[战斗](https://book.leveldesignbook.com/process/combat)、[敌人设计](https://book.leveldesignbook.com/process/combat/enemy)、[遭遇](https://book.leveldesignbook.com/process/combat/encounter)、[掩体](https://book.leveldesignbook.com/process/combat/cover)、[地图平衡](https://book.leveldesignbook.com/process/combat/balance)。依据 CC BY-NC-SA 4.0 改编与重组。

## 1. 区分系统设计与遭遇设计

战斗系统定义移动、瞄准、攻击、伤害、资源、防御、敌人行为与反馈。遭遇则将这些能力组织到特定情境中。

如果核心攻击难以读懂，或移动不可靠，换一个更好的房间也未必能解决问题。应识别问题属于机制、编排，还是二者的交互。

设计战斗之前，确定：

- 玩家的移动与攻击能力。
- 预期信息与反应机会。
- 敌人的感知、触及范围、机动性与失效状态。
- 可用生命值、弹药、能力和补充方式。
- 预期难度、失败成本与受众。

伤害数值只是有效压力的一部分。暴露、精度、预警、距离、行进时间、掩体与复合威胁都会改变结果。

## 2. 将敌人设计为可读的关系

有用的敌人职责会让玩家有理由采取不同动作。职责可能是施加距离压力、迫使玩家移位、封锁位置、要求优先处理、惩罚暴露，或支援其他敌人。

对每种职责，明确：

- 玩家在受罚之前能够感知什么。
- 该敌人鼓励哪种行动或情境。
- 可以学会哪些弱点或反制手段。
- 与其他职责组合时会发生什么变化。
- 关卡如何为其行为提供足够空间。

不要将更好的 AI 等同于更高智力、全知或最大杀伤力。行为应支撑预期体验，并传达状态。

尤其在潜行中，要区分感知与判断。怀疑、调查、搜索、警戒与恢复需要可读线索和可行的信息模型。具体实现取决于项目。

## 3. 围绕一个问题构建遭遇

使用简洁的遭遇简报：

- 预期决策、感受或技能。
- 起始视野、玩家状态与资源。
- 敌人职责、位置、巡逻与到场条件。
- 相关几何、高度、掩体、路线与出口。
- 升级、增援、完成、失败与重置条件。
- 预期替代进路与可能的漏洞利用。
- 能够证明遭遇有效的证据。

### 工作顺序

1. 建立足以支持行动的入口视野。
2. 让首次投入行动有成本，并有可理解的替代选择。
3. 编排敌人职责，使其相互作用真正重要。
4. 为移动、恢复或有意的限制提供空间。
5. 适当改变条件，而不只是增加数量。
6. 定义玩家撤退、绕过、猛冲或返回时会发生什么。
7. 使用合理的入场资源测试，而不只是让全副武装的作者测试。

“竞技场”并不自动意味着带锁门的圆形房间。限制、生成和波次结构都是必须服务于目标的选择。

### 用原型验证离开掩体的理由

在一项射击游戏改编练习中，复用已有的一个远程敌人和一个逼近型敌人。问题是：它们的位置能否让换掩体变得有用，同时保留可理解的退路。这是待测配置，不是玩家行为报告。

在入口前方放一根高柱，房间对面放远程守卫，侧面通道供逼近型敌人使用。保留返回入口的退路。每次试验都采用相同武器、生命值、弹药、敌人设置和敌人警戒状态；从实际项目记录这些数值。

| 关系           | 预期决策                         | 首项实现检查                                       |
| -------------- | -------------------------------- | -------------------------------------------------- |
| 入口到高柱     | 进入以获得更好角度，同时保留退路 | 玩家受击前能看见守卫；高柱确实阻挡其射击           |
| 高柱到守卫     | 探身或换位攻击                   | 镜头显示的安全程度与武器起点的暴露符合预期掩体行为 |
| 侧面通道到高柱 | 逼近型敌人威胁当前位置时换位     | 敌人能穿过通道，并在攻击前给出可感知预警           |
| 退回入口       | 恢复或重新考虑，而不是被困       | 玩家能够退出；敌人按已定义规则跟随或停下           |

先只运行守卫，再只运行逼近型敌人，最后同时运行两者。寻路失败或敌人射穿高柱属于实现缺陷，应先修复，再判断组合效果。组合测试中，记录首次投入行动、换掩体、伤害来源、撤退，以及完成或失败。如果玩家留在入口，调查那里是否已经提供全部所需攻击角度；不要自动提高敌人伤害。

比较几何时，只改变高柱或侧路关系，保留其他设置。将玩家瞬移到下一掩体位置的脚本命令，不能证明玩家能够发现并走过该路线。

### 难度调整

考虑改变组合、位置、资源、信息、时机和行为，而不只是生命值或伤害。验证改动是否保留预期教学内容，且没有移除反制空间。

高难战斗可能是合适的。因果不清、不可避免的伤害、失效的镜头视野或过度重复，可能是另一类问题。

## 4. 掩体是视线与保护系统

掩体包括任何能阻挡相关视线或攻击的结构，并不限于齐胸高箱子或显式掩体机制。

按照游戏实际支持的内容描述掩体：

- 部分遮挡与完全遮挡。
- 站立与蹲伏使用。
- 实质防护与仅供隐蔽。
- 可穿透、可破坏、临时或可移动行为。
- 方向性、宽度、深度、边缘暴露与附近移动选项。

### 评估关系，而非物件数量

- 从每个位置能看到和打到什么？
- 在位置之间移动时，什么会暴露？
- 受保护位置是否创造决策，还是允许无限期不行动？
- 敌人能否以可读方式接近、包抄、驱离或封锁它？
- 双方能否读懂同样的轮廓与碰撞边界？
- 镜头是否暗示安全，而受击盒或武器起点仍然暴露？

到处添加掩体可能割裂视线、阻碍移动、削弱远程职责或降低紧迫感。掩体过少则可能剥夺战术选择。不存在普遍正确的密度。

### 诊断停滞的掩体战

**问题：** 玩家从不离开第一个安全位置。

**追溯：** 该位置看得到所有必要目标，提供补给，也没有实质弱点；推进只会增加风险。

**小幅干预：** 调整其视野、资源获取、与目标的关系，或某个敌人的可读压力。不要仅为强迫移动而添加任意惩罚。

**测试：** 观察移动现在能否产生可理解的优势，同时不消除有用的防守玩法。

## 5. 单人挑战与多人公平不同

单人遭遇可以刻意创造不对称和预设压力。成功与否取决于预期挑战、可读性、资源和恢复。

竞技地图必须考虑规则、技巧、团队配合、生成行为、资源经济与控制权变化。视觉对称的地图仍可能不公平，不对称地图也可以提供平衡机会。

### 地图平衡审查

| 关系         | 问题                                                     |
| ------------ | -------------------------------------------------------- |
| 起点与生成点 | 玩家能否在危险出现前辨明方向？对手能否预测或封锁生成点？ |
| 到达时机     | 在实际移动下，谁先到达争夺物品、射击角度或目标？         |
| 视线         | 哪些距离与武器占优？暴露的成本是什么？                   |
| 路线         | 侧袭路线是否可用、可辨认，且值得付出行进成本？           |
| 高度         | 信息与攻击优势以什么为代价？                             |
| 资源         | 奖励会促成移动与争夺，还是强化永久控制？                 |
| 瓶颈         | 它们创造决策，还是仅仅移除选项？                         |
| 轮转         | 玩家能否应对变化的目标，而不是总有一条路线胜出？         |
| 恢复         | 落后方能否有意义地重新投入游玩？                         |
| 人数         | 地图在预期玩家人数与模式下是否仍有效？                   |

没有针对具体规则的理由时，不要强加三路图式、等长路径或精确镜像。

### 时间测量表

对相关路线测量：

- 从生成到接敌。
- 从生成到目标／物品。
- 目标之间的轮转。
- 暴露在争夺视线中的时间。
- 从重生到重新交战。
- 资源与目标循环。

使用有代表性的玩家与移动选项测量。距离除以最高速度只是近似值，不是对局证据。

## 6. 结合情境测试平衡

记录地图版本、模式、人数、队伍、经验、规则和重大事件。检查优势在哪里形成，而不只是最后谁赢。

有用证据包括：

- 交换阵营后的回合。
- 重复测得的争夺时机。
- 被选择的路线和持续被忽视的路线。
- 控制权、资源持有、死亡与恢复模式。
- 来自新手和熟练玩家双方的反馈。

来自小规模且实力不均群体的胜率，不能证明阵营优势。热力图可以定位活动，却不能单独解释原因。

竞技技巧也会演进。当社区发现新的移动方式、战术或资源时机，曾经无人挑战的关系也会改变。应把平衡视为持续探究。

### 成对检查到达时机

针对一个争夺拾取物，标出两个出生点和拾取物的激活边界。固定模式、装备、移动选项和出发信号。让同样两名测试者从相对两侧出发，交换阵营，再重复这一对试验。逐次记录测试者、阵营、路线、输入／起步时刻、到达事件和中断；保留同时到达及通行失败的尝试。

这项改编检查要判断表面阵营优势是跟随出生点，还是跟随测试者。使用共享时钟或游戏事件日志计时，而不是两份未同步录像。如果交换测试者后优势仍跟随某条路线，先检查其转弯、暴露和必要移动，再改变拾取物位置。这些短程运行调查到达机会，不能证明整场对局公平。

## 交付物

提供遭遇或地图假设、带注释的关系、已有的实测时间／状态，以及一项带后续测试的优先改动。不要仅凭平面图或单场对局就声称“已平衡”。
