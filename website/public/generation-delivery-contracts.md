# Generation jobs, artifact delivery and asset acquisition

Follow a generation request from submission through completion, download, and asset validation. Check provider-specific job states, failure responses, and artifact lifetimes before building an adapter. For usage rights, see [provider and model terms](generative-api-boundaries.md).

## A job ID is not an imported asset

Preserve submission identity, raw provider state, version/model choices, input hashes, output roles and the target project revision. Distinguish transport failure, remote execution failure, missing artifact, expired URL, integration failure and quality rejection. Do not infer create-request idempotency from a correlation ID, or cancellation/refund from a client timeout. Signed URLs belong in controlled operational storage, not public logs.

## Replicate file acquisition and terminal accounting

Official rolling documentation checked 2026-10-18; no prediction, SDK, authenticated request, file download or webhook was executed. The [create guide](https://replicate.com/docs/topics/predictions/create-a-prediction) separates HTTP waiting via Prefer: wait from the Cancel-After cancellation deadline. An incomplete sync response does not establish remote cancellation. Some JSON examples say successful, whereas polling prose and the [lifecycle reference](https://replicate.com/docs/topics/predictions/lifecycle) use succeeded; canceled and aborted are also documented outcomes. Do not adopt the simplified success/failure loop as a complete state machine.

The [file-output guide](https://replicate.com/docs/topics/predictions/output-files) attributes FileOutput defaults to client libraries 1.0.0 and also documents optional URL-return behavior. Python byte readers/iterators and JavaScript streams still require completed persistence. No exact current or installed SDK was checked. Its migration advice removes manual Authorization handling for FileOutput, while the [HTTP reference](https://replicate.com/docs/reference/http) addresses direct file-URL authorization. These concern different access paths and do not establish a contradiction; direct-download requirements and SDK handling were not resolved here. Never forward a service credential to an output host based on a generic example.

**Proposed acceptance, unimplemented:** archive each available output with role/index, bytes/hash, prediction/model/version identity and retained inputs/logs; then reconcile terminal execution and accounting separately. A file handle or surviving prediction ID is not a durable artifact. Provider timing metrics are not a final invoice. The [retention policy](https://replicate.com/docs/topics/predictions/data-retention) distinguishes API and Web predictions; exact retention-clock origin, renewal and post-removal recovery remain unverified.

A future fixture should separate processing-with-files, terminal success with archived files, success after data removal, truncated copies, and sync-wait expiry followed by later completion. None automatically authorizes another chargeable submission. Freeze candidate bytes and provenance before selection, retain acquisition failures in the denominator, and require separate target-engine acceptance. Output rights, reproducibility and endpoint-specific charges remain unresolved.

## ComfyUI: queue, execution events and files are separate surfaces

The [route documentation](https://docs.comfy.org/development/comfyui-server/comms_routes) describes validation and queueing; [execution messages](https://docs.comfy.org/development/comfyui-server/comms_messages) distinguish success, error and interruption for a prompt. An executed message is a UI update, not a universal whole-graph success signal.

At the [inspected server revision](https://github.com/Comfy-Org/ComfyUI/blob/c06bf5f569d268b80076e5f44126f87cdf835869/server.py), a caller-selected UUID is accepted without a duplicate-ID check before enqueue. The targeted cancellation path handles queued/running work and checks running-job identity; finished or unknown IDs return cancelled:false. This is a source snapshot, not a minimum supported release. It does not prove that an external service request or custom node stops or refunds when interrupted.

The [same-revision image example](https://github.com/Comfy-Org/ComfyUI/blob/c06bf5f569d268b80076e5f44126f87cdf835869/script_examples/websockets_api_example.py) resolves history output descriptors through /view; binary WebSocket data is preview evidence. Its image descriptors do not define every video/audio/custom-node output schema.

**Proposed fixture:** disconnect the client after accepted submission, reconcile queue/history without resubmission, include a cached node and failing output node, and compare expected output roles with archived bytes. Record custom-node and checkpoint revisions separately. Restart durability and external-side-effect rollback remain unknown; a shared-worker global interrupt is not an acceptable substitute for task-scoped control.

### Capture Wwise authoring SoundBanks before testing runtime playback

**Evidence scope:** Official Wwise SDK **2024.1.9.8920** documentation, checked 2026-10-18; documented-only, no SDK installation or execution. The initially requested 2024.1.5 URL redirected to 2024.1.9, so this is not evidence for 2024.1.5 behavior.

**API/input/output boundary.** [`ak.wwise.core.soundbank.generate`](https://www.audiokinetic.com/en/public-library/2024.1.9_8920/?id=ak_wwise_core_soundbank_generate.html&source=SDK) is synchronous. Inputs select user-defined SoundBanks, platforms and languages. An empty bank list generates all user-defined banks; all auto-defined banks are generated regardless of that list. Missing platform/language lists expand to all platforms/languages by default; `skipLanguages=true` suppresses localized SoundBanks. `writeToDisk` defaults to false: without disk output, subscribe to `ak.wwise.core.soundbank.generated` for bank structure information and base64 bank data. The call result contains generation logs, not a runtime-load or playback result. Those logs are empty in WwiseConsole. Error severity affects operation integrity; Fatal Error prevents completion. `clearAudioFileCache` clears the entire audio cache across platforms, even when generation selects fewer platforms.

**Proposed harness gate, not an upstream guarantee.** Record authoring version/project revision and an explicit bank/platform/language manifest, including `skipLanguages`, before generation. Establish the generated-topic subscription before a no-disk request; retain the received payloads and their hashes, or verify the requested files when disk output is enabled. Review diagnostics separately from RPC completion, and do not accept an empty WwiseConsole log as positive validation. Check actual output coverage rather than assuming the requested user-bank list is the complete generated set. Treat authoring generation, captured artifact persistence, native bank loading and event execution as separate gates. This note establishes neither notification replay after disconnect nor timeout cancellation, retry idempotence or rollback. If receipt is uncertain, preserve evidence and inspect outputs before retrying. Cache clearing requires separately authorized scope; it is not a harmless repair switch.

**Unimplemented fixture:** selected user bank plus an auto-defined bank; omitted language/platform lists; no-disk generation with a missed notification; generation diagnostics; WwiseConsole empty-log behavior. No engine integration, entitlement, redistribution or audible-success claim follows from this documentation.

## Proposed acceptance and recovery envelope

Use the [asset-validation contracts](asset-validation-contracts.md) and [export/import work order](production-work-orders.md#1-export-an-authored-asset-import-it-and-audit-dependencies) for the next boundary after delivery; remote terminal status is not validated import.

Preserve originals and parent/derivative relationships; evaluate artifact bytes, format, dimensions/duration, geometry/material/rig properties and target-project behavior separately from remote success. Include late results, expired URLs, duplicate notifications, empty child-job sets, partial outputs and stale project revisions in a future fixture. Reconcile outstanding work before another chargeable submission. Require task approval before deleting artifacts, creating credentials, accepting terms, or making another chargeable submission.
