# Engines, rendering libraries, and content tools: sources and scope

Source review date: 2026-10-18. The primary data file, `data/segments/engines.json`, contains 22 entries organized by their actual roles. Godot, Unity, and UE are game engines; Phaser is a browser 2D framework; Three.js is a 3D rendering library; React Three Fiber is a React renderer for Three.js; and Blender is a content creation tool. None should be labeled an end-to-end game agent.

## Engineering guidance for game development planning

- **Record versions together.** Each task should retain engine, package, plugin, renderer, and documentation versions. Godot demo master, Three.js dev, and Blender main can be newer than the installed runtime. Check versions first when an API is missing.
- **Establish minimal project feedback first.** Confirm that the engine launches, assets import, logs are readable, and a minimal scene runs before adding complex gameplay. Headless checks, editor checks, and the exported runtime cover different behavior.
- **Observe state and visuals separately.** Unit tests check pure logic. Cross-frame, Play mode, or Functional Tests check lifecycle behavior. Screenshots, input traces, and actual play assess the final experience.
- **Physics issues often depend on timing and configuration.** Godot grounded / floating modes; Unity FixedUpdate / Update timing, contact normals, collision layers, and ground rays; and Phaser static-body refreshes can all affect behavior. Rewriting only the controller script may leave the root cause intact.
- **Blender-to-engine delivery is a conversion pipeline.** Fix units, axes, object transforms, material models, texture color spaces, rig names, and animation names. Check glTF / GLB export and import in the actual runtime. Validate file conformance, visual appearance, and collision behavior separately.
- **Three.js flexibility leaves system design decisions to the project.** A rendering library can be combined with physics, navigation, ECS, input, audio, and save systems. Identify who provides each system. R3F organizes React scenes; it does not choose the simulation architecture.
- **Preserve reproduction conditions for community experience.** Author tutorials explain causes and engineering tradeoffs. Record versions, test scenes, hardware, source code, and failure cases; one demo or frame rate is not a capability ranking.

MCP integrations and practical agent skills live in `agents.json`. Game AI entries maintain Unity agent plugin and CLI lifecycle information, avoiding duplicate counts in engine infrastructure.
