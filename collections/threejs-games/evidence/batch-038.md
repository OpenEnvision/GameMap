## Rotor Rush

- Source: [momenbuilds/rotor-rush](https://github.com/momenbuilds/rotor-rush/tree/13c795979b53de6b12c747b2d8d209f459285fea), commit `13c795979b53de6b12c747b2d8d209f459285fea`.
- Rendering: The actual index loads bootstrap.js, whose Start handler dynamically imports main.js and starts the game. main directly creates THREE.WebGLRenderer and owns the update/render animation frame for the player, volumetric city and aerial gates. DOM pilot selection is a lightweight shell, not a rendering framework. [Renderer source](https://github.com/momenbuilds/rotor-rush/blob/13c795979b53de6b12c747b2d8d209f459285fea/src/main.js#L1-L14).
- Game loop: The flight updates the next visible gate in sequence. Bringing the player's 3D position within 5.5 units hides that gate, awards virtual followers and advances checkpoint; clearing the final gate calls finishGame. That changes state to finished and displays elapsed time and the run's virtual follower score, with reset/replay controls. [Gameplay source](https://github.com/momenbuilds/rotor-rush/blob/13c795979b53de6b12c747b2d8d209f459285fea/src/main.js#L635-L647).
- Dependencies: Three is the only declared npm runtime dependency, with Vite development tooling. Authored vector/velocity/fuel movement, gate proximity checks, instanced scenery, DOM input/HUD and a Web Audio rotor tone implement the flight game without a physics/render framework. The bootstrap delays the Three game import until Start. Local WebP textures provide pilot/celebrity faces; other city/player geometry and UI labels are constructed in code. The reviewed stylesheet uses system fonts. The scoped flight source has no account/social-backend integration; follower totals are game-score values, not real audience data.
