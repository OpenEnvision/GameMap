英文原文

Check generated assets at each handoff: file format, geometry, materials, animation, dependencies, and engine import. Use the format-specific requirements below to build acceptance checks for your target toolchain.

1. Validate a portable asset without confusing format validity with fidelity

Documented operations and fields. The glTF 2.0 specification specifies meters, radians, right-handed coordinates and positive Y up. The Khronos Validator validates glTF 2.0 and produces JSON issues and asset statistics. glTF Transform supplies read/edit/write APIs, extension packages and a batch CLI. Assimp converts supported imports to a common in-memory representation but exports only a subset of formats. Import support is therefore a different capability from export support.

Proposed acceptance contract. Before transformation, record units/basis, extension inventory, external resource identities, scene hierarchy, material slots and animation/skin expectations. Retain the complete validator report and tool version for both original and candidate. Treat unsupported required extensions and missing external resources as explicit blockers. Then compare the candidate's geometry, scene identities and sampled deformation in the actual consuming importer. A structurally valid asset can still lose intended material behavior, animation or collision semantics.

Failure/recovery/persistence. Preserve originals and transform settings. An importer returning an object is not proof that every authored feature survived. Retry corrected candidates in new output locations; never overwrite the only source or infer atomic export/rollback from a successful function return. Fresh-process reopen plus an external-resource inventory is an additional proposed gate.

Unimplemented fixture: one asymmetric skinned object, one required extension, one missing texture and a declared animation sample. Compare before/after reports and target-engine state rather than a single preview image.

Version/license scope: glTF 2.0 is the format scope; exact specification revision and implementation versions are unpinned. Validator declares Apache-2.0; Assimp documents modified three-clause BSD. glTF Transform's license at checked commit 8e2a94a is MIT; dependency and input-asset terms remain separate. Earlier Validator commit resolution was rate-limited; no immutable revision is invented.

Gaussian-splat editing and delivery

A spatial Gaussian asset needs a renderer-specific export/import contract. The following inspected behavior complements mesh/interchange validation; no editor, importer or round-trip was executed.

Source and version scope

  • UnityGaussianSplatting selected commit 2c6fed37da67a217367261fcfcd3316d34c73e76 is a later main-branch snapshot, not the v1.1.1 tag. Its package manifest still declares 1.1.1 / Unity 2022.3.7f1; the v1.1.1 tag points to different commit 9310dce438da726244ace17eaf6f768826435fa4. Do not conflate a package version with the tested/source commit.

1. Export a delivery asset, preserve a separate editing project

SuperSplat's ordinary export gathers visible, nonempty scene layers; its default does not mean “export selected Gaussians only.” Selection filtering is an optional serializer setting, also used for copy/paste. Deletion removes instances from the live list, with undo records; selected-and-locked instances are excluded from selection-driven deletion. Crop-by-select/invert/delete is therefore different from merely drawing a selection or hiding a whole layer.

Evidence: visible-layer collection, default filter, deletion and undo, official cleanup recipe.

The .ssproj path writes document JSON, camera/view/timeline/pose settings, original resource rows and per-layer instance/palette data. Ordinary splat export instead bakes edits and does not serialize those editor-state records. Importantly, project saving is not an unconditional deleted-data archive: normal compact saves drop rows unreferenced by any layer; an in-place save keeps rows so current-session undo can still access them. Do not infer that undo history survives reopening.

Evidence: project data and compaction, in-place exception, instance flags/palettes.

2. Record transform application, SH bands and irreversible metadata loss

Ordinary SuperSplat export composes a -180° Z rotation (described in code as undoing the load-time convention), the entity world matrix, and the per-instance transform palette. It transforms positions, rotations and scales, rotates retained SH coefficients, and bakes color/transparency grading. The internal keepWorldTransform=true option skips the world/PLY-flip part; it does not suppress palette transforms. These facts are a source-specific convention, not a universal axis-conversion recipe.

The export source explicitly declares one LOD, model: 'default', and extraColumns: []. Its comment says the editing pipeline does not carry antialiased/2DGS trained-model tags through loading. SH output is capped by the chosen maximum and available data. Therefore an uncompressed export is not proof of preservation of original metadata, LOD structure, arbitrary custom columns or all SH bands.

Evidence: transform composition, export schema and bands, attribute/SH/grade baking.

3. Compression changes membership as well as precision

In this SuperSplat UI path, compressed PLY, SOG and SPZ set minimum opacity to 1/255 and enable the implementation's invalid-data filter; ordinary PLY does not enable those settings. The predicate drops source sigmoid opacity strictly below the threshold, before the later grading step. “Invalid” follows the actual attribute-specific predicates, not a blanket rule forbidding every infinite raw log-domain value.

Official rolling documentation distinguishes uncompressed PLY from quantized compressed PLY and lossy SOG; SOG is not merely a lossless zip of the original attributes. Selection count, decoded survivor count and requested SH bands must accompany the file size.

Evidence: format-specific settings, filter predicate, import/export formats, SOG specification.

4. “SPZ supported” is not an importer compatibility contract

SuperSplat's pinned serializer exposes SPZ versions 3 and 4, default 4. The selected Unity importer explicitly requires SPZ header version 2 and throws otherwise. This is a statically established version mismatch, not an observed failed import. Changing SuperSplat from SPZ 4 to SPZ 3 does not satisfy that importer.

Unity routes only .ply and .spz; its PLY reader requires binary little-endian 1.0, and the Gaussian reader requires float-valued position, DC color, opacity, scale and quaternion attributes. General mesh PLY, ASCII PLY, SOG and a filename ending in .ply are not substitutes for that schema. Required-field validation does not check complete higher-order SH preservation.

Evidence: SuperSplat SPZ versions, default SPZ 4, Unity SPZ rejection, PLY encoding, routing/schema.

5. Unity editing/export has its own quality and coordinate boundary

The pinned Unity editing guide advises Very High import quality for editing because lower presets are already quantized/approximated. Export excludes deleted and cutout Gaussians; the documented world-space option bakes transforms and rotates SH. Cutouts are visual inclusion/exclusion volumes, not collision bodies. Manual editing has no Undo; the guide suggests disabling/re-enabling the renderer to revert all edits.

Do not generalize “world-space export” to proven arbitrary hierarchy/scaling fidelity. The implementation passes localRotation/localScale alongside localToWorldMatrix; the shader separately handles axis-sign flips and explicitly limits that handling. Nested transforms, nonuniform scaling and reflections require a fixture rather than an assumed round-trip guarantee.

Evidence: editing guide, export survivor/write path, transform arguments, shader transform.

6. Nonempty artifact, bounds and visual observation are separate gates

The checked SuperSplat writeSplatFile path returns early without calling a writer when zero Gaussians pass export filtering; the enclosing scene.write path can still return true. Consequently the return value alone is not evidence of a nonempty delivered artifact. Browser-file close and abort operations exist, but crash durability and end-user download completion have not been established here.

Its inspected editor bounds reduce transformed centers; they are not full Gaussian support extents, collision volume or a walkable mesh. Unity's checked view-color path evaluates stored SH against camera direction and opacity; that is not evidence of reconstruction into relightable PBR materials. Ordinary PLY export also does not promise a camera trajectory: SuperSplat's viewer settings and .ssproj store camera information separately; Unity can import a separate cameras.json.

Evidence: zero-survivor source, early return, success return, writer close/abort, center bounds, view color, viewer camera settings, Unity camera input.

No inspected splat-export interface produces mesh connectivity, gameplay rules or collision acceptance. Separate collision-generation tools may exist; this note does not claim Gaussian-splat applications can never support collision.

2. Preserve USD composition and resolve managed assets deliberately

Documented operations and fields. UsdStage exposes composition, variants, payload loading, save and flatten operations. Save() excludes session layers; dirty anonymous layers require explicit export. Flattening resolves composition rather than retaining the original editable structure. GetUsedLayers() is a snapshot affected by load set and variant selections, not an inventory of every possible configuration. GetTimeCodesPerSecond() returns the stage time-code rate, with documented metadata fallback rules. The broader OpenUSD documentation describes the scene-composition toolset. Blender 4.4 USD interchange supports a subset of USD data and documents USDZ limitations including UDIM textures; this is not a claim about later Blender versions.

OpenAssetIO examples require a concrete manager plugin; some examples explicitly cannot work without one. An asset-management API does not supply a configured asset database or guarantee a resolvable entity.

Proposed acceptance contract. Capture root/session/edit-target identity, selected variants, payload load policy, time metadata, resolver/manager identity and resolved resource manifest. Choose either an editable composition deliverable or a flattened evaluated deliverable before writing. Make session edits intended for delivery explicit. Open the candidate in a fresh process with the intended resolver and compare required variants and time samples.

Failure/recovery/persistence. Missing manager, unresolved references, unsaved anonymous layers or missing session edits block promotion. Preserve unresolved identifiers and diagnostics rather than replacing them with guessed local paths. Save failure is not permission to flatten and discard composition. Re-resolve only under the same recorded manager/configuration, or label a changed resolution as a new candidate. Transactional multi-layer saves and cross-manager equivalence remain unknown.

Unimplemented fixture: a session-only variant choice, anonymous edited layer, unloaded payload and manager-resolved reference. Require both serialized-artifact inventory and cold-reopen observations.

Version/license scope: OpenUSD release and OpenAssetIO examples are rolling; exact library/license and plugin terms were not established in these inspected pages. Blender evidence is specifically 4.4. The focused packaging review below pins selected OpenUSD sources; it does not establish installed-library, resolver-plugin or asset rights. No studio asset server was accessed.

OpenUSD packaging: dependency discovery is not portable closure

Sources checked 2026-10-19; static source inspection only. This selected-version review complements the composition/save guidance with dependency-discovery scope, package mutation policy and package acceptance; it does not establish a runnable adapter.

Version scope. The official v25.05 tag reference resolved to 25f3d3d84440d0a80cb27f7e3383f2e71d8cfb28. This selected source version does not identify the installed runtime or latest release.

UsdUtilsComputeAllDependencies returns recursive layer, non-layer asset and unresolved-path collections. Its Boolean is not an assertion that unresolved paths are empty.

Thus even an empty unresolved list does not certify that this case was covered. Use fresh result containers; in this revision the layer output is appended to, despite the header's general clearing description. This is a static contract discrepancy, not an observed production failure.
  • Localization traversal visits authored variant specs and payload/reference fields rather than only a stage's selected composition. It therefore differs from GetUsedLayers()'s current stage snapshot. Clip-template discovery requires a filesystem directory in this implementation. Do not label this traversal universal closure for arbitrary resolver-generated dependencies.
  • The packaging API requires caller-configured resolver context, localizes paths and serializes encountered anonymous layers. Directory dependencies are ignored, not recursively bundled. Proposed acceptance contract, unimplemented. Record root identifier/hash, resolver/context identity, discovery callback and exclusions, intended composition/variant/payload scope, package flavor, first-layer name and mutation flag. Keep enumeration Boolean, layers/assets/unresolved lists, unsupported discovery cases, packaging Boolean and complete diagnostics separate. Before promotion, reconcile a project-owned expected dependency manifest against actual package membership and rewritten paths; flag ignored directories and unsupported clip-template cases explicitly. Reopen from a relocated package in a fresh consumer without access to the original asset tree, then test the required variants, payloads and time samples. This is a bounded portability claim for that consumer/configuration, not all possible scene configurations.

Preserve source bytes and use an isolated candidate destination. Reject unresolved required assets, unexpected skipped members or unauthorized flattening. Do not repair by removing references, changing resolver context or enabling in-place edits silently. Package creation and target acceptance are separate verdicts; interruption rollback and multi-file durability remain unverified.

Unexecuted fixtures: a missing texture, unselected variant reference, unloaded payload, directory-valued dependency, clip template inside a package, package-member collision, and ARKit packaging of external composition. Compare declared coverage, diagnostics, membership and cold-reopen observations, not only file existence or a return value. No DCC installation, upstream code execution, asset download or runtime compatibility claim accompanies this proposal.

3. Keep material graphs, color processing and texture compression separate

Documented operations and fields. MaterialX represents material networks, values and assignments with standard processing/shading nodes; its official implementation repository supplies code and Python interfaces. OpenColorIO documentation describes configurable color management and ACES workflows. KTX-Software provides KTX2/Basis Universal tooling, creation/conversion/comparison/extraction operations and JavaScript/WebAssembly interfaces. A complete source checkout requires Git LFS content.

Proposed acceptance contract. Extend the texture-export work order with three manifests: material graph and supported node implementations; selected color configuration/transforms; container/codec and actual target transcode format. Keep color textures separate from normal/mask/data textures. Record decoded dimensions, mip levels, channel meaning and alpha policy, then inspect the intended material under target rendering conditions. File/container support alone does not establish acceptable GPU texture fidelity or renderer parity.

Failure/recovery/persistence. Missing node implementation, missing LFS bytes, unsupported transcode target or unknown source color interpretation leaves acceptance incomplete. Preserve the uncompressed master, graph, configuration and compressed derivative hashes. Retry a changed encoder/quality/transcode target as a new candidate. Do not silently substitute a shader, apply a display transform twice or label an incomplete source checkout buildable. Cross-renderer visual equivalence and interrupted-export durability remain unverified.

Unimplemented fixture: a color ramp, alpha edge, packed data map and normal map across two supported target formats, with declared error tolerances and an engine-rendered observation. This adds compression/graph coverage to the prior texture work order rather than repeating its image-inventory gate.

Version/license scope: the overview links above are rolling; installed MaterialX node library, OCIO configuration and KTX encoder/transcoder versions are unknown. Validation success needs a named policy

For a glTF pipeline, the proposed check is ktx validate --gltf-basisu --warnings-as-errors --format json asset.ktx2. This is a documented command proposal, not an executed result. --gltf-basisu enables the extension-specific checks; ordinary KTX validation is not the same policy. Warnings are not errors unless requested. When validation reaches report generation, stdout includes valid and a messages array, with issue IDs, types, messages and details. Preserve stdout and stderr separately, together with version and exit status. Argument, input-opening and early fatal errors need not produce JSON; missing or malformed JSON is a tool/report failure, not an automatic asset verdict.

The documented exit categories are 0 success, 1 argument failure, 2 I/O failure, 3 invalid input, 4 runtime/library failure, 5 unsupported operation/state, and 6 unimplemented feature. Validation failure throws the invalid-input category. Distinguish asset rejection from infrastructure/tool failures instead of labeling every nonzero exit “bad texture.”

Pinned sources: validator, exit codes and report formats.

Normal-mode changes the shader contract

--normal-mode accepts linear textures with at least two components. Three/four-channel input is treated as XYZ unit normals; the fourth channel is discarded, and XY is repacked as RGB=X, A=Y. The documented reconstruction samples GA and rebuilds positive Z. This is a channel-layout transformation, not just a quality preset. Reject the preset unless the consuming shader explicitly implements that layout; retain a material-slot/encoding/channel-layout record.

--normalize on a two-component input normalizes a 2D vector; its documentation explicitly warns against using that result to generate XY normals with --normal-mode. Separately, assignment of a transfer function and conversion of pixel values are different operations. Prefer explicit intent and --fail-on-color-conversions when unexpected conversion must fail the build.

Pinned sources: normal-mode contract, normalization and transfer-function options.

Transcodable container is a separate gate

The pinned transcode command requires BasisLZ or a UASTC DFD color model. It explicitly rejects an input that does not need transcoding as invalid input. Merely having a valid .ktx2 container is insufficient. Without an explicit target, the command chooses uncompressed r8/rg8/rgb8/rgba8 based on channel count. Record the requested target and inspect output format; successful conversion alone does not prove the intended compressed GPU representation was produced.

Pinned source: transcode implementation and help. Its embedded raw-only wording conflicts with the implementation's KTX2 writer; do not repeat that wording as an established restriction without a focused upstream clarification/test.

4. Optimize, retopologize, unwrap and regenerate tangents without losing correspondence

Documented operations and fields. meshoptimizer at f0a684f1 provides GPU-oriented optimization, simplification and compression, with gltfpack and a JavaScript subset. Draco at d429de84 compresses meshes/point clouds and provides JavaScript/WebAssembly decoders; its documentation recommends version-specific decoder URLs. These operations do not themselves establish a target importer's extension/decoder compatibility.

At the inspected meshoptimizer snapshot, basic simplification error is approximate and relative to mesh extents; topology/error limits can stop reduction before the requested index count. SimplifyErrorAbsolute changes input and reported error to absolute units; otherwise simplifyScale converts error units. Proposed gate: retain source units, error mode, requested/actual index counts and returned error separately from rendered or deformation fidelity.

The vertex codec is lossless, while preceding quantization and vertex filters can lose information. Its documented default vertex/index bitstream versions are both 1, compatible with v0.23+/v0.14+ respectively; those compatibility guarantees concern point releases and exclude development branches. Record bitstream version as well as encoder/decoder identity. Draco's documented encoder CLI defaults position quantization to 11 bits; zero disables quantization only for the specified attribute. Its versioned decoder-URL guidance addresses propagation/cache mismatches. Proposed gate: retain per-attribute quantization/filter settings and compare the final decoded candidate with the original; a codec label is not pipeline-wide fidelity evidence. No encoding, decoding or simplification was executed for this review.

xatlas at f700c779 separates charting and packing. UV seams can increase output vertex count; a progress callback returning false requests cancellation. Its output header defines Vertex.xref as the output-to-input vertex mapping and uv in atlas-dimension units, not normalized coordinates. Ignored faces remain with UV (0,0) and atlasIndex -1, so nonempty output does not establish complete usable atlas coverage. MikkTSpace's pinned header returns tangents per face-vertex and warns against averaging or overwriting through the old index list. Baker/renderer triangulation must match. Its implementation skips non-triangle/non-quad faces and conditionally invokes output callbacks; a true return alone does not prove every input face received stored tangents. These are source observations, not reproduced failures. UVAtlas exposes create/partition/pack and remapping APIs, but was archived April 24, 2026; upstream discourages use for new projects.

Instant Meshes documents orientation-field then position-field solving with interactive guidance. That workflow is not evidence of a headless automation API. QuadriFlow processes OBJ geometry; its documented solver selection changes dependency licensing. Neither remesher establishes preserved skinning or animation-ready edge flow.

Proposed acceptance contract. Freeze source topology and attribute ownership → create an optimization/retopology candidate → establish explicit old/new correspondence where available → unwrap and apply vertex remaps to all affected attributes → regenerate compatible tangents → bake/decode/import → compare geometry, UV seams, normal response and sampled deformation. Record decoder, triangulation and target extension support. Same index count is not proof of unchanged vertex identity.

Failure/recovery/persistence. Lost weight/morph correspondence, UV overlap, changed tangent signs, unsupported decoder or excessive geometric error blocks promotion. Restart from the preserved preceding stage after correcting parameters; do not repair by guessing old indices. In the pinned xatlas repack path, prior output is destroyed before cancellable packing. The output array and meshCount are initialized before the per-mesh loop; cancellation between mesh outputs can leave later entries unbuilt. Do not infer complete output from meshCount or assume every cancellation has the same partial state. Preserve the preceding artifact separately and validate per-mesh/face coverage. These static paths were not executed. Archive only validated stage outputs as reusable inputs; generic interruption/retry guarantees remain unknown.

Unimplemented fixture: mirrored UVs, a seam requiring duplicated vertices, an asymmetric quad with fixed triangulation, a skin-weight boundary and a known silhouette. Evaluate under motion and lighting; compression ratio and quad count are not quality scores.

Collision cooking and gameplay-shape acceptance

For Unity 6000.0, check collision geometry after import and before navigation or traversal testing. Match the checks to the engine patch and physics configuration used by your project.

Validate geometry before relaxing cooking safeguards

MeshCollider.cookingOptions controls conversion into physics query/contact support structures. With validity checks disabled, valid inputs are the caller's responsibility and invalid data can produce undefined behavior. This is a separate operation from visual mesh import or format validation. cookingOptions.

Unity requires an alternative validator if cleaning or vertex welding is disabled: cleaning-off meshes must avoid degenerate triangles, including near-zero/infinite-area examples; welding-off meshes must not contain colocated vertices. Accept the collision shape

Concave MeshColliders are supported as static or kinematic geometry, and collide with convex colliders rather than other concave colliders. Convex conversion fills concavities into a hull. Mesh collider introduction.

Convex geometry has no holes/entrances and must have nonzero volume. Unity may thicken a convex plane/quad by up to 0.05 times its longest in-plane dimension. Thus even a visually correct plane or doorway can acquire materially different collision geometry. convex.

Proposed gate: define allowed doorway clearance, ledge height, wall thickness and hull approximation error before choosing convex versus triangle-mesh/compound representation. The Aseprite file specification defines slice pivots relative to the slice origin. 1. Decode identities before mapping engine cells

Tiled GIDs are map-local. The same tile can acquire another GID when tilesets change order. Interpret the value as unsigned 32-bit, extract flags, and clear all four high bits before lookup: horizontal 0x80000000, vertical 0x40000000, diagonal/hex-60 0x20000000, hex-120 0x10000000. Clear the fourth flag even for non-hexagonal maps. Zero denotes an empty cell; otherwise choose the largest firstgid not exceeding the stripped value, then subtract it. Orthogonal/isometric transforms apply diagonal swapping before horizontal/vertical flips; hexagonal flags have different semantics. GID contract, pinned documentation.

A valid range is insufficient: image-collection tilesets can have gaps, including local IDs above tilecount. External TSX files omit map-specific firstgid. Verify actual tile existence and preserve tileset identity plus local ID as the transfer key. TMX tilesets.

Godot atlas transformations instead use alternative-ID flags 4096, 8192, 16384; raw Tiled GIDs cannot be copied into them.
