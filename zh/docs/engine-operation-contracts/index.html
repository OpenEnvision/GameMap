引擎操作：完成、恢复与验证

英文原文

Identify when an engine operation has completed, which artifacts to inspect, and how to recover from failure. Each reference links the relevant API, command, or implementation.

How to read an operation

Record the exact tool/engine version, execution mode, project/world identity, requested operation, native result, output artifacts, and acceptance condition. Keep request acceptance, operation completion, persisted output, and fresh-session reopen separate. A tool name or successful process launch does not prove gameplay correctness.

Runtime animation observation gates

For Unity 6000.0 and Godot 4.4, observe pose application, playback completion, event delivery, and actor movement separately. Pair these checks with pose and compression validation and frame capture ownership.

Unity: observation depends on visibility, update phase and movement owner

  • AlwaysAnimate includes offscreen animation. CullUpdateTransforms suppresses retargeting, IK and Transform writes when renderers are invisible; CullCompletely suppresses animation altogether when renderers are not visible. A stale offscreen skeleton therefore cannot alone establish an incorrect clip or graph. [U1]
  • Normal updates in Update, Fixed in FixedUpdate, and UnscaledTime ignores Time.timeScale. Record the mode and relevant clock rather than comparing identical render-frame counts as identical animation progress. [U2]
  • OnAnimatorMove occurs after state-machine/animation evaluation but before OnAnimatorIK; treating this callback as the final post-IK pose boundary is unsupported. [U3]
  • applyRootMotion has no effect when a script implements OnAnimatorMove, and changing it at runtime reinitializes the Animator. Record the movement-owning script; do not treat toggling the property as a harmless observation control or a proven reset/rollback operation. [U4]

Editorial fixture, unexecuted: fixed clip/controller/rig with nonzero travel and an IK target; compare visible/offscreen runs for each culling mode. Log animation time, sampled joints, post-IK joints and actor transform separately. Repeat with a movement callback and with timeScale changes under each update mode. Introduce the root-motion toggle as a separate reinitialization case, not between nominally equivalent samples. Pass criteria must name which phase and movement owner they test.

Godot: immediate pose, playback completion and side effects differ

play() applies animation on the next processing opportunity; advance(0) requests the immediate update. seek(seconds, update=true) updates the pose while skipping intervening events. Its update_only=true suppresses method, audio and animation-playback tracks. Seeking to the end does not emit animation_finished; the documented alternative for skipping while emitting completion is advance(). These are distinct operations, not interchangeable shortcuts. [G1]

Manual process mode requires advance(). mixer_applied reports application of blended results to target objects; it is not documented as a rendering/physics fence. Deferred method mode batches calls until after event processing, whereas immediate mode invokes them as reached. Looping animations do not emit animation_finished. The transform of a valid configured root-motion bone track of type POSITION_3D, ROTATION_3D or SCALE_3D is visually canceled, so an in-place skeleton is not by itself failed locomotion. Animated-node caches may miss a disappeared node; clear_caches() forces refresh. [G2]

Editorial fixture, unexecuted: one nonlooping clip with a moving joint, a method marker and completion counter; compare fresh-instance play plus advance(0), seek with both update flags, and timed manual advancement. Record target pose, marker count, completion count and callback mode as separate results. Add a looping variant with an explicitly bounded sample interval rather than waiting for completion. Replace an animated target node and test cache refresh separately. For root motion, compare extracted motion and the consuming controller's world transform against the skeleton view; specify exactly one movement owner.

Acceptance boundary and unknowns

Proposed evidence record: engine patch version, clip/rig/graph identity, initial state, evaluation clock and step sequence, visibility/culling mode, callback mode, observation phase, joint pose, actor transform and event log. This is an editorial test design, not an implemented harness.

The cited contracts do not establish a universal rendered-frame barrier, completion of deferred application-specific side effects, physics/contact success, safe retries after ambiguous evaluation, rollback, persistence across reload, or cross-platform numerical determinism. Project scripts and exact patch behavior remain untested. Do not infer those guarantees from an evaluation call, pose signal, animation-finished signal or screenshot.

Native GUI automation is a separate evidence surface

Windows UI Automation depends on provider-supported control patterns. It does not establish that Unreal, Unity, or Blender exposes every custom widget or scene object. Invoke is intended to return promptly, but provider behavior varies. Neither invocation success nor SendInput's inserted-event count proves application completion.

Bind each GUI action to a current process/window/control observation; retain physical-coordinate and screenshot-transform metadata; verify focus and clickability; stop on permission or integrity failures. Do not use a screenshot of a success message as the sole evidence for asset persistence. The documented Graphics Capture picker flow includes user consent and exposes frame time, size and buffer lifetime. It captures UI pixels rather than an engine simulation checkpoint.

Runtime locale changes: separate string delivery, rendering and accessibility

Documented operations. Unity Localization 1.5 documentation, identifying package 1.5.13 at inspection, says the first LocalizedString.StringChanged subscription initiates loading and receives the value after completion; locale/reference changes and supported variable changes trigger updates. Additional subscribers added after loading completes receive the latest loaded value. StringChanged.

RefreshString() returns whether a refresh could be requested. A request made while the current loading operation is still executing is ignored and returns false. Thus a refresh call is not a guaranteed update, and its Boolean is not rendered-output evidence. RefreshString.

Source-inspected native semantics. Godot 4.5-stable Button handles translation-change notification by translating and shaping text, updating minimum size, and separately queuing accessibility update and redraw. Its accessibility-update handler chooses translated text when no explicit accessible name exists; when both differ, it combines the explicit name and translated text. An empty-text/name button can fall back to tooltip text. This is source behavior, not evidence that any screen reader received or announced it. button.cpp, lines 188–219 at inspected commit. Godot 4.5 separately exposes accessible names, descriptions, relationships and live-region mode. Control reference.

Proposed acceptance contract, unimplemented/unexecuted. Record engine/package/build, requested locale, table/key, formatting inputs, font assets, control identity and a locale-change generation identifier. Collect separately: accepted/rejected refresh request; delivered localized value; bound control value; post-layout rendered frame; native accessible name/role/state and observed assistive-technology behavior. Do not collapse these into a single “locale changed” success.

Failure/recovery fixture. Change locale while a string is loading, alter a dynamic argument, then change locale again. Record ignored refreshes and apply a bounded application retry only after the relevant operation settles; accept only evidence matching the intended final locale and inputs. Include an expanded or RTL label, an icon-only button, and a button whose explicit accessible name differs from translated text. Check clipping, shaping/fallback, focus continuity, semantic naming and announced updates independently. Missing semantic/assistive-technology evidence remains unverified, even when screenshots pass.

Version boundary. Unity’s @1.5 URL is a version-family documentation route, not an immutable package pin. Godot 4.5-stable was resolved to inspected commit 876b290332ec6f2e6d173d08162a02aa7e6ca46d; this pins source, not a measured installed build. No cross-platform screen-reader coverage, timing guarantee or rendering/accessibility synchronization guarantee is established.

Godot native semantic observation and action completion

Native accessibility adds a semantic observation/action surface alongside pixels and authoritative project state. The following source-inspected contract complements the locale/name behavior above; it does not establish an installed observer or assistive-technology test.

Source and version scope

The inspected Godot 4.5-stable tag resolves to commit 876b290332ec6f2e6d173d08162a02aa7e6ca46d, verified through the official GitHub ref API. This is historical, version-specific source evidence, not a claim about all later Godot releases. Its third-party inventory identifies accesskit-c 0.17.0, upstream revision f69571eca23151be07a41bf493ca48a2b44b6a8b, MIT. That inventory identifies vendored headers, not an installed dynamic library. Tag, inventory.

Godot's release announcement calls the 4.5 integration experimental and describes incomplete editor support. Do not translate that launch statement into a current-release limitation without checking the target release. Official announcement.

Activation is an input, not an empty-tree verdict

The 4.5 project setting accessibility/general/accessibility_support has Auto=0, Always Active=1, Disabled=2. Auto processes information updates only when an assistive application is active. Accessibility inspectors do not count; the documented inspector-testing mode is Always Active. The update-rate setting defaults to 60 per second. 4.5 ProjectSettings.

DisplayServer.accessibility_screen_reader_active() returns 1 for active, 0 for inactive and −1 for unknown. Source distinguishes supported from enabled: both require the display capability and a non-disabled mode, while enabled also requires exactly 1 in Auto. Thus unsupported, disabled, inactive and unknown must remain separate outcomes. Pinned API, gating.

Update, focus and action completion

queue_accessibility_update() returns no completion token; it queues only an in-tree node outside the edited scene. get_accessibility_element() is documented for use during NOTIFICATION_ACCESSIBILITY_UPDATE, not as a general snapshot query. Ordinary Node elements begin as containers with node names/children. Exit/invalidation frees the RID, so it is not a persistent project object identifier. Node API, queue/element creation, default semantics, exit.

The changed-node queue is a set of object IDs, so repeated pre-flush queue requests coalesce. Processing is window-specific, skips invalid/non-visible-window nodes, and calculates semantic focus from the window/control focus owner, including embedded windows and popups. Flushing is enabled-gated and rate-limited unless forced. These operations are not rendering or assistive-announcement fences. Update/focus/flush implementation.

FOCUS_ACCESSIBILITY eligibility depends on accessibility-enabled state and visibility. An Always Active inspector test can therefore change the focusable set compared with inactive Auto. Source also registers focus/blur callbacks that call grab_focus()/release_focus(). Eligibility, callbacks, registration.

Accessibility actions advertise a supported action and register a callback receiving one action-dependent Variant. The AccessKit bridge validates the target, converts request data and invokes a valid registered callback with call_deferred; receipt is not effect completion. Semantic setters and action registration are update-phase gated. A Button's accessibility click changes toggle state/emits callbacks, then separately queues semantic update and redraw. Action API, deferred bridge, registration gate, Button effect.

Adapter implication: record action delivery, callback execution, project-authoritative effect, refreshed native semantic observation, rendered frame and actual assistive behavior independently. Do not retry a potentially non-idempotent action merely because speech or tree refresh is late.

Custom gameplay and platform limits

Adapter implication: custom-drawn controls/gameplay need project-authored semantic mappings appropriate to the intended roles, descriptions, state/value and actions; default names/hierarchy are not automatic interpretation of pixels, collision, quest completion or spatial playability. The low-level 4.5 DisplayServer API supports this semantic authoring, including sub-elements; it does not supply an external scene-state oracle. Pinned DisplayServer API.

The 4.5 documented screen-reader capability covers Windows, macOS and Linux X11/Wayland. Verify the actual build's capability: Windows source conditions it on a live accessibility driver, and initialization failure clears that driver. Do not infer mobile/Web delivery from the engine's export list. 4.5 capability, Windows capability, driver initialization.

Pinned DisplayServerHeadless::has_feature() always returns false. Combined with the initial capability check in SceneTree::is_accessibility_enabled() and its flush guard, this gates off the normal SceneTree→native-driver update path even in Always Active. This does not rule out a synthetic/custom unit-test tree; such a test still would not prove native OS delivery or assistive usability. Headless, enabled/flush gates.

Proposed acceptance fixture: explicitly unimplemented and unexecuted

Use a disposable project-owned screen with a toggle action, a custom-drawn status indicator backed by independently observable state, an accessibility-only focus target, and a popup. Freeze the expected semantic contract and action effect before execution.

  • Record exact engine/template and AccessKit build, OS/display driver, mode/override, configured update rate, native observer and assistive-technology versions, process/window identity, scene generation, transient element mapping and request timestamps
  • Compare Auto with absent/present assistive technology against Always Active inspector observation; preserve inactive/unknown/unsupported distinctly. Use headless only as a negative capability case
  • Change the custom state repeatedly before a flush and test final-generation semantics without demanding an event for every coalesced request. Deliberately omit its semantic update while changing pixels/state; the collector must detect stale semantics
  • Invoke the advertised action and observe callback, authoritative state, native tree and pixels separately. Exercise popup focus, hide/reveal, and removal/recreation to reject stale element identities. Recheck before any retry
  • Acceptance requires matching intended state/generation on each claimed surface within a declared observation timeout. A timeout is incomplete evidence, not automatic action failure or permission to repeat it. Actual screen-reader interaction and disabled-player review remain separate; no automated accessibility or legal certification is established

Necessary but currently unimplemented components are a project driver, native semantic observer, action/effect correlation and platform-specific assistive review. The proposal neither claims those collectors already exist nor replaces existing visual and authoritative-state checks.

One useful integration fixture

Suggested check: use a disposable door scene to connect object identification, asset edits, streaming/physics readiness, actual interaction, temporal capture, save and fresh reopen. Include an interrupted action and a stale-reference case. Declare expected world-state transitions and image/geometry tolerances before running. If the project-specific interaction API or event observer is missing, report that gap rather than substituting generic editor dispatch.

The remaining unknowns include platform-specific renderer behavior, installed plugin compatibility, complete reset ownership, save durability under interruption, and project-specific quest/reward transactions. None of the source checks above supplies those runtime results.

Additional checked interface references

These references preserve useful operational context; they are not separate directory cards in this update. Sources checked; full reproduction not performed.

Bevy · Remote Protocol

Exposes ECS inspection and mutation through a JSON-RPC interface embedded in a Bevy application. RemotePlugin installs protocol operations but does not start a transport; RemoteHttpPlugin adds HTTP communication. Queries depend on registered, reflectable types, and non-strict reads can include per-component errors. The source link pins the file reviewed, not an executed build. Network access and mutation permissions require an explicit application policy. Primary source. Windowless renderer example at checked commit.

Houdini Engine · PDG API

Controls procedural task-graph cooking and retrieves work-item events, states, and output paths. HAPI supports asynchronous full cooking, polling, pause, and cancellation; generate-only mode is always blocking even when the blocking argument is zero. Cached success differs from newly executed work, and a new cook can discard uncollected events. Preserve scheduler paths and drain events before another cook. Cancellation must be followed by terminal-state inspection. Houdini licensing and host configuration remain deployment requirements. Primary source. PDG function reference. Command-line Python and license lifecycle.

O3DE · Editor Automation

Exposes editor functionality through Python bindings and external editor-test orchestration. The PythonEditorBindings gem exposes editor C++ functionality through EBus and requires project configuration and an editor rebuild. External pytest and LyTestTools can launch the editor while embedded scripts drive it. Preserve both external and editor logs. These interfaces do not establish runtime Python support or a graphics-free execution profile. Primary source. Parallel editor test patterns.

Maya · Standalone Python and File Operations

Initializes Maya outside an interactive session for scripted scene processing. Standalone initialization provides Maya libraries to Python scripts; file commands handle opening, saving, references, and import/export. Initialization and cleanup are session-sensitive, so code running inside Maya must not blindly repeat standalone initialization. Preserve native references, plugin dependencies, and save/reopen evidence; a batch process is not proof of target-engine compatibility. Primary source. Maya 2026 file command.

Substance 3D Painter · Remote Control

Connects an external process to Painter scripting through its remote-control interface. Useful for driving an already running authoring application from a pipeline tool. The remote interface is distinct from headless texture baking and does not by itself establish a complete material-export contract. Qualify application version, project state, export preset, destination files, and downstream texture/color interpretation. Primary source.

Navigation after procedural world edits

Reference: RecastNavigation commit 9f4ce64458dfae86e1239c525ddc219c4e9e06f1. The query semantics below concern upstream Detour; check how your engine binding exposes them.

Detour query and rebuild chain

1. Resolve endpoints and budgets. API documentation says findNearestPoly can leave nearestRef = 0 and the output point unchanged when nothing matches; implementation still returns success after that search. Require nonzero endpoint references and record search extents, snapped positions, agent/build parameters and filter. Keep search-node budget, polygon-corridor capacity and straight-point capacity separate; init documents at most 65,535 nodes. [S3–S4]

2. Classify corridor results. findPath returns ordered polygon references. The documented undersized-buffer behavior is a prefix from the start; unreachable destinations return a best available corridor. Static implementation can combine DT_SUCCESS with DT_PARTIAL_RESULT, DT_OUT_OF_NODES and/or DT_BUFFER_TOO_SMALL. The success helper checks only its high-level bit. Preserve the entire status, count, capacities and final polygon. A capacity-truncated corridor need not have PARTIAL_RESULT when the search itself reached the destination. Growing the output buffer does not increase the search-node pool. [S5–S6]

3. Own sliced-query state. The documented sequence is initialize, update within iteration budgets until terminal, then finalize. The filter pointer must survive the query; source documentation warns that intervening non-sliced calls can corrupt its state. Static inspection shows update can report success after exhausting the frontier; finalization adds the partial-result detail and resets query state. finalizeSlicedFindPathPartial intentionally recovers a visited portion of an existing corridor and can lack PARTIAL_RESULT when such a polygon is found. Therefore compare the returned endpoint with the requested goal regardless of flags. Proposed adapter gate: isolate query ownership and invalidate/restart after relevant navigation changes; snapshot consistency, cancellation rollback and concurrent mutation safety were not established. [S3, S7]

4. Extract corners without upgrading reachability. findStraightPath clamps endpoints to the first/last supplied polygons. Its END flag and zero endpoint polygon reference identify that corridor's endpoint, not original-target arrival. An invalid intermediate portal can yield success plus partial output. At this pin, filling the straight-point capacity can set BUFFER_TOO_SMALL even when END is emitted: treat saturation conservatively and retry with headroom where needed. Keep off-mesh traversal execution as a separate game action. [S8]

5. Revalidate after obstacle edits. Documentation invalidates tile/polygon references on tile removal, while changing polygon flags/areas leaves references intact. Restoring the original reference is possible only under the documented original-parameters/reference conditions. Tile-cache rebuild implementation removes/replaces tiles without requesting the old reference; cached corridors therefore need freshness and traversal checks. [S9, S13]

Obstacle additions/removals enqueue work. The documented completion surface is repeated update(..., &upToDate); static inspection rebuilds at most one queued tile per call. At the exact commit above, it removes pending work and advances obstacle bookkeeping even after a rebuild failure; upToDate merely tests empty queues. This is a static source observation, not a reproduced engine bug. Preserve every update status: later successful drain cannot erase an earlier failure. Hardcoded capacities are eight touched tiles per obstacle and 64 request/update entries, not guaranteed useful coverage; bounded tile collection can truncate silently. Proposed gate: validate footprint/burst bounds, retain rebuild failures and requery affected routes after drain. [S10–S12]

Evidence and availability boundary

Record pin, navmesh generation, filter, input/snapped endpoints, capacities, all statuses, returned corridor/corners and obstacle-update history. Proposed acceptance requires the intended endpoint plus fresh game-level collision, locomotion, off-mesh-action and arrival evidence. A valid navmesh path never establishes collision-free game arrival by itself.

Recast/Detour are available C++ libraries under the zlib license; DetourCrowd is a separate movement/avoidance module. Preserve applicable license notices and alteration attribution. Availability is not an installed GameMap adapter, MCP server or tested engine integration. Persistence, crash recovery and whole-game reset remain unverified. [S1–S2]

Engine-facing update and arrival boundaries
