Fair pi-based recursive harness improvement

When adapting a harness, implement the controls below alongside the extension and optimizer surfaces in the pi/GEPA reference.

For generated interaction regressions, stateful discovery and failure reduction separates adaptive shrinking, clean-state reproduction and fixed regression promotion. Count every reset, attempted step, shrink/replay and cleanup; reduced traces are not independent success-rate trials.

Choose the unit of comparison first

  • Official reproduction: preserve the publisher's exact tasks, evaluator, engine, allowed observations/actions, budgets and run policy. A new pi adapter must meet those conditions before its score is compared with published results.
  • Harness improvement study: freeze one released task/evaluator revision, compare baseline and candidate on the same declared conditions, and identify results as a new study. Replacing engine checks with vision judging, adding privileged state, or extending the feedback budget changes the experiment.
  • Protocol-inspired fixture: when evaluator/data are unreleased or rights unresolved, create original tasks and tests that exercise the documented idea. Name the protocol influence without claiming the source benchmark's score or task coverage.

Harness selection: statistical independence and adaptive feedback

Checked 2026-10-18. Primary-source inspection only; no installation, benchmark execution or game-performance claim. The proposed protocol below extends the existing candidate-selection and reproducibility records.

rliable: repeat whole tournaments, preserve the intended comparison

Agarwal et al. assume independent runs per task, each yielding a scalar normalized score. Appendix A.4 treats best-of-N as a distinct stochastic algorithm: one maximum over N candidates supplies only one run of that selection algorithm. It therefore needs independent repetition. Stratified bootstrap resamples runs within each task. The Atari coverage study shows nominal 95% CIs under-cover with three runs; percentile intervals perform well around ten for examined aggregate metrics. These empirical results do not establish a universal sample-size guarantee. Paper v4, §2, §4.1, Fig. 6, Appendix A.4

At inspected commit 3ccd9f4dea577a04d3d2b557f259aac08badbd81, get_interval_estimates takes method-to-score mappings shaped (runs, tasks, ...) plus an aggregate function, returning point estimates and lower/upper CI arrays. Defaults are percentile, 50,000 bootstrap replications and 95% nominal coverage. The single-array route supports task_bootstrap: false resamples runs on fixed tasks; true additionally resamples task columns. Tuple/list-valued entries instead use StratifiedIndependentBootstrap, independently resampling arrays without task_bootstrap. That convenience route is not a paired A/B effect interval. For matched mean differences, a pair-aligned difference matrix can use the single-array route; nonlinear contrasts need a verified pair-preserving route. This is an API-path limitation, not a claim that the entire library cannot support paired analysis. Pinned library

IQM trims 25% from each tail of pooled scores. Probability of improvement averages taskwise Mann–Whitney rank statistics; it is not a posterior probability of being the best system. Metrics

The public code is Apache-2.0; setup declares 1.2.0 and arch >= 5.3.1, < 8.0. The repository is archived. Its older README dependency example is not a runtime lock. Setup, license, README, repository

Adaptive holdout: an independent evaluator can still leak selection feedback

Dwork et al. distinguish independently fixed candidates from ones adapted using previous holdout feedback; ordinary static multiple-testing treatment does not automatically cover the latter. Thresholdout takes training/holdout datasets, threshold, noise scale and overfitting budget, answering bounded queries phi: X -> [0,1]. Below a noisy discrepancy threshold it returns the training mean; otherwise it returns a noisy holdout mean and spends budget. It stops when exhausted. Theorem 9 requires i.i.d. holdout samples, calibrated parameters/sample size and mediated access. This is not a guarantee for unrestricted visual critiques, correlated project variants or unlimited binary feedback. NeurIPS 2015, §1, §3, Theorem 9

The inspected release evidence establishes paper/pseudocode, not an official executable package or software license. The arXiv record is v2, September 25, 2015, with a non-exclusive distribution license. Record, license

GEPA execution controls: counts, caches and resumed evidence

Checked 2026-10-18. Read-only source inspection at f1cfdee2856e9dc4b5b4dc5cc2e391d0aa20d819, the revision already used for the adapter review. No external code, models or evaluations were run. These are code-level boundaries and proposed tests, not reproduced overspending or game-performance findings. The MIT license does not supply model-service or asset rights.

Count proposal tasks separately from iterations and retained candidates

The sampling strategies can produce one, N or P×N parent/minibatch tasks per iteration. However, MaxCandidateProposalsStopper checks state.i, which the main loop increments once per iteration. Equal settings therefore do not guarantee equal actual proposal counts. MaxTrackedCandidatesStopper counts the retained candidate pool, not all failed, skipped or discarded proposals. This does not imply every sampled task produces a new candidate. Parent selection is called repeatedly without a distinct-parent constraint in these samplers; the strategy name alone does not establish unique parents.

Proposed GameMap control: retain separate iteration, proposal-task, generated-proposal, unique-candidate, admitted-candidate, actual-evaluation and cache-hit counts. Match actual search resources when comparing broader sampling against a better selector, and preserve costs for discarded branches.

A stop condition is not hard admission control or remote cancellation

MaxMetricCallsStopper compares accumulated evaluation count. On a fresh run, engine.run evaluates the seed on the validation batch before reaching the main loop's stop check. This static path does not guarantee rejecting an over-budget initial batch before execution. The loop-boundary check does not itself cancel an in-flight model, renderer or evaluator. TimeoutStopCondition starts its clock at object construction, not automatically at remote-job submission.

There is a concrete cost-tracking caveat: optimize wraps an ordinary reflection_lm callable lacking total_cost in TrackingLM. That wrapper estimates tokens but reports cost 0.0; a positive max_reflection_cost alone cannot trip on that path. The separate custom reflection_strategy path has additional cost-capability checks and must not be conflated with it. Even supported reflection-cost accounting does not automatically include task-model, renderer, tool or human costs.

Proposed GameMap control: reserve a bounded batch budget before dispatch; independently enforce call, rendering and wall-time limits; record in-flight work and final reconciliation. Probe whether cost measurement is supported rather than interpreting zero as free. Verify executor/service cancellation separately. Use a no-external-call mock adapter for limit tests, not a live paid endpoint.

Cache hits and resume are not independent repetitions

EvaluationCache keys contain a candidate-text hash, train/val namespace and example ID. Distinct train/val loaders already have separate namespaces; the same loader deliberately shares one. ListDataLoader uses positions as IDs, not content hashes. The key has no independent model, engine, evaluator, asset, environment or trial identity fields; callers must encode or invalidate those changes themselves.

The API contract and engine reuse the saved seed's validation evidence when gepa_state.bin exists; an identical supplied seed already in the pool causes no extra seed evaluation. A supplied seed absent from that pool is instead evaluated and added before the main stop check, also advancing state.i. Migration discards old unnamespaced cache entries but leaves previously recorded validation scores intact. Disabling evaluation caching does not itself erase those candidate scores or start a fresh experiment. Additionally, the engine's full-validation path bypasses cache when write_agent_state is enabled so it can capture trajectories: richer recording is not necessarily cost-neutral.

Proposed GameMap control: bind data contents/order, model/engine/adapter/evaluator versions, assets and reset policy into an experiment fingerprint. Use a fresh run directory for semantic changes rather than reusing saved scoring state. For independent stochastic trials, use fresh state or explicit trial-aware identities; returning the same cached observation does not add a sample. Record trace/cache settings and distinguish cumulative resumed results from newly executed work. GEPA's valset is used for selection and defaults to trainset when omitted; keep final assessment outside optimization rather than treating that parameter name as a protected test split.

Unimplemented acceptance fixtures: zero remaining budget with a larger initial validation batch; actual task/proposal counts under N and P×N sampling; a callable without real cost tracking; rejection of incompatible resume after dataset reordering or evaluator changes; actual evaluation counts with cache/trace settings toggled; and independent repeats of the same candidate. None was executed, and no general vulnerability or capability gain is asserted.

Bind evaluation results to the complete candidate composition and the path that executed it. The GEPA and Meta-Harness references below describe their respective implementations; the Meta-Harness case concerns its classification harness.

1. GEPA: named components are not a typed execution graph

At f1cfdee2856e9dc4b5b4dc5cc2e391d0aa20d819, adapter.py defines Candidate as dict[str,str]. evaluate(batch,candidate,capture_traces) must construct the system and return aligned outputs/scores and, when requested, trajectories; make_reflective_dataset returns per-component JSON-serializable records. ProposalFn explicitly permits coupled updates. Component selection offers one component in round-robin order or all keys.

The mutation implementation copies the parent and asserts each returned replacement key already exists (585–588); this assignment does not itself check membership in components_to_update or enforce semantic dependencies. Merge requires identical component-key sets and takes whole component texts from descendants sharing an ancestor. When both descendants changed a component, executable code chooses the higher aggregate-score descendant, randomly breaking ties (159–190), despite an adjacent comment describing proportional random selection. It does not synthesize or type-check their combined workflow.

Candidate hashing is SHA-256 over JSON-serialized sorted candidate items (37–39). This identifies text, not the builder, tool implementation, operation authority or external runtime. Existing cache warnings remain correct.

Proposed GameMap adaptation, unimplemented: retain the GEPA map, e.g. tool_schema, workflow and evidence_policy, rather than claim GEPA supplies a graph language. Freeze a builder interface: validate_and_build(candidate, frozen_contract) returns either a plan or structured invalid_candidate reasons. Declare primitive operation IDs, argument/result schemas, dependency edges, sequential/parallel execution, bounded retries and error branches. Validate the mutation mask and coupled-schema compatibility before evaluation. Keep evaluator/permissions outside candidate text. Identify an executable candidate with component-text hash plus builder revision, primitive/schema manifest, dependency lock and fixed authority hash; keep experiment/trial identity separate. Store parent IDs and the chosen component provenance for merges.

2. GEPA: “metric calls” depend on the execution path

EvaluationBatch has optional num_metric_calls. Reflective evaluation honors it for parents and children, falling back to batch length (372–376, 638–642). Full validation instead charges len(val_ids) with traces and len(uncached) otherwise (287–368). The merge/cache evaluator likewise returns requested/cache-miss example counts. Therefore num_metric_calls is not a universal accounting override for nested model calls or retries.

Reflective batch counts are incremented after a batch returns. The default batch adapter evaluates pairs sequentially; if a later call raises after earlier external work, that path does not provide a complete spent-resource count. Batched reflection failure also triggers per-task retries (245–272); additional attempted work must be retained. These are static paths, not reproduced overspending.

Proposed control: maintain an append-only dispatch/settlement ledger outside optimizer scores: candidate/trial/task/operation IDs; phase; reserved budget; attempts; observed model tokens, tool/render calls and wall time; charged/estimated/unknown cost; terminal status. Reconcile cancellation and late results. Keep valid task failure, invalid candidate, infrastructure failure, timeout, abstention and unknown outcome distinct, even if a declared optimization metric assigns some the same failure score. A missing usage report is unknown, not zero. Budget admission and total-cost reconciliation remain adapter/executor responsibilities.

3. Meta-Harness: a concrete interface and incomplete-coverage boundary

At 8123ccabe2b19fa1123090b2e5f1bacc20963ce8, the classification example’s MemorySystem requires predict(input) → (answer,metadata), learn_from_batch(results), get_state() → serialized string and set_state(state). Its loader imports a module and instantiates the first inspected MemorySystem subclass (479–504). The outer validation checks zero process exit status plus stdout containing OK when importing the candidate (192–215); that is narrower than validating the runtime interface and is already code execution, not safe static inspection.

benchmark.py requires complete configured seed groups per model/dataset/candidate (179–239), but aggregate-frontier construction averages accuracy over the dataset groups actually loaded, without requiring every configured dataset for each candidate (675–688). Its context-character axis instead averages only strictly positive context lengths and then truncates to an integer; these axes therefore use different inclusion rules. The outer summary similarly averages available datasets (529–540). Zero score is labeled “failed”; invalid imports disappear from the normal summary when other candidates are valid (232–244, 490–560). Preserve a complete manifest rather than treating those summaries as exhaustive failure denominators.

The Pareto axis is memory_context_chars, not total model cost. MemorySystem tracks the last prompt per thread and defines context length in characters. The actual classification evaluation uses the last tracked call_llm prompt length minus test-input length, clamped to zero and integer-averaged (inner_loop.py 439–469); this includes template text as well as memory, rather than serialized-state size or all prompts. Its evaluated metric does not call the default get_context_length path. benchmark.py separately sums available runtime, call and token fields, with missing fields defaulting to zero. Do not rename character efficiency as token or spending efficiency.

Proposed control: content-address candidate code plus dependencies/configuration; record the exact exported class instead of relying on module names. Require complete prespecified dataset/seed coverage for promotion, report coverage separately, and retain every proposal/import/evaluation attempt. Validate interfaces without importing untrusted candidates; later runtime validation requires a separately authorized isolated environment.

Browser-game virtual time: stepping and suspension are different experiments

Sources checked 2026-10-19. Read-only review of Microsoft Playwright v1.64.1, whose tag resolves to cfe490d941f992655948eee8fd4fd94e1c4234bf. This selected release matches GameMap's declared development dependency, not a verified benchmark runtime. The repository license is Apache-2.0; it does not clear browser binaries, tested games or their assets. No upstream code, browser or game was executed.

Source-backed temporal boundaries

  • Choose what time means. The Clock API distinguishes setFixedTime (fixed Date values while timers continue), setSystemTime (change wall time without firing timers), runFor (advance through callbacks), and fastForward/pauseAt (jump, firing overdue timers at most once). Thus replacing a five-second gameplay interval with a five-second jump can change how many update callbacks run. That consequence is GameMap's application to game tests, not a measured game defect.
  • The animation cadence is synthetic. Injected source supplies animation callbacks with simulated ticks and schedules each new frame request for the next 16 ms boundary; the unit tests assert this grid. A jump can instead deliver an already-overdue frame at its destination, because the jump path reschedules overdue timers there. This is not measured display refresh, GPU throughput or evidence that the game uses a 60 Hz physics step. Timer creation schedules a zero-delay timer created during a tick one millisecond later. Tests show that such a nested callback at the requested endpoint needs another advance, including when scheduled through a microtask.
  • Installation and isolation are explicit inputs. The guide warns that installation must precede use of the replaced timer APIs. The API's scope is the entire browser context, including its pages and iframes, not one isolated page. Server dispatch applies clock operations to frames and preserves initialization instructions for later documents. Do not treat sibling pages as independent time-controlled trials or infer worker, Web Audio, network/server or whole-browser synchronization from that scope.
  • Manual advance is not an instantaneous, atomic step. runFor and its timer loop continue processing due timers after catching a synchronous callback Error, advance the clock, then rethrow the first Error. A browser test expects a later callback to run before rejection. The callback invoker yields through a real timer after each callback and does not await a callback's returned promise. A rejected advance therefore does not imply unchanged state or safe retry; its completion is not a network/asset-readiness barrier.
  • Keep performance measurement outside this treatment. The performance replacement makes performance.now() follow simulated ticks. For the performance methods copied by this implementation, entry queries return empty arrays and mark/measure calls return synthetic entries. These readings cannot substantiate native frame-time or resource-timing claims. Separate real-clock performance runs from virtual-time functional runs.

Proposed acceptance contract, not executed

Record game/build hash, Playwright and actual browser revision, context identity, initialization/readiness policy, clock mode, starting wall/monotonic values, ordered clock commands and input events, randomness/reset policy, application tick counters, callback/error trace and post-step state. The release's browser inventory is an expected dependency list, not proof of the installed executable.

Use an explicitly quiescent game-start boundary after bootstrap; a large pauseAt jump during active gameplay is itself a suspension treatment. Confirm the starting state before issuing player input. Keep real-clock play, fully stepped virtual time and suspend/resume probes as distinct conditions with separately declared oracles. Require an application-owned completion signal for asynchronous effects rather than adding arbitrary extra simulated time until a test passes.

Unexecuted fixtures:

  1. In separate fresh contexts, start identical movement on positive 100 ms intervals and cooldown logic after the same paused baseline; compare runFor(1000) with fastForward(1000). Record callback counts, elapsed-time calculations and final state. Different results can reflect the declared temporal treatment, not automatically a game bug.
  2. Record the starting simulated-tick phase and advance a self-rescheduling animation loop just before and onto its next 16 ms-grid boundaries. From a timer callback firing at endpoint T, schedule a nested zero-delay follow-up: assert absence at T and presence after a predeclared advance to T+1, rather than waiting indefinitely at T or silently extending the budget.
  3. Make one timer throw new Error(...) before another mutates score. Retain the rejection and resulting state, then discard that trial context rather than blindly repeating the advance.
  4. Include a sibling page and a separately observed worker/audio or server deadline where used. Establish which clocks actually move; unsupported synchronization leaves that fixture outside the virtual-time claim.

These are original proposed harness checks. They do not establish deterministic simulation, synchronized external clocks, delivered rendered frames, reproducible benchmark scores or real-time performance.

Harness²: contrastive task-local edits and reusable improvement evidence

The October 9 paper, v1, studies frozen-model harness adaptation on professional-work benchmarks, not game production. It proposes invariant and domain-specific edits, probes them on the same task, then composes a successor from execution contrasts. Those contrasts do not certify correctness. GameCraft-Bench: the upstream replay-to-score contract

GameCraft-Bench evaluates complete Godot projects and agent-supplied demonstrations. At upstream a4334753, shared by the later adapters, traces remain development-visible; “hidden” describes the evaluation rubric's role, not secret test trajectories. Named scenarios may initialize advanced states. Credit therefore concerns demonstrated requirements, not independently discovered playability or enjoyment. This source audit ran no games or judges.

Evidence budget. The task contract asks for 1–10 traces, capped at 600 frames at 30 FPS. With overridable defaults, the scorer keeps the first ten filenames before replay. Each fresh launch defaults to a 1280×720 input viewport and resized 854×480 MP4. The frame sampler defaults to 0.5-second spacing and, for longer recordings, a contiguous 20-second window seeded by demo name; a short recording can have its final frame cloned. Replay separately defaults to a 90-second limit. These are distinct submission, replay and observation limits.

The OpenAI judge, defaulting to GPT-5.5, sends at most 40 sampled PNGs, as do the released Claude/Kimi paths. The Gemini path sends the full MP4 instead. The sampling window is not a universal video-duration cap; provider choice can change evidence modality as well as judgment.

Aggregation and failures. Each rubric item uses max (default) or mean across scored demos; different items can win on different playthroughs. The inspected task rubric combines item averages with a build gate and mechanics/depth/visuals/art weights of 15/35/15/35. A caught replay failure is logged and skipped, shrinking a mean's demo denominator. By contrast, five failed judge attempts produce item zeros for that replayed demo. Missing, null or non-numeric answers, including “NA,” also become zero; there is no coverage-exclusion rule. No successful evidence leaves requirements at zero.
