开发路径

制作 2D 游戏

从游戏简报到可分发构建，沿着小步、可重复的流程推进。

2D

Playable game loops

项目预览

  • OpenGame · Portal runner
  • OpenGame · Space-station skirmish
01
开发步骤

规划与范围

定义玩家动作、胜负条件和目标平台，让首个版本集中在一个可重复的核心循环上。

重点

找到核心乐趣

主题

  • Game brief
  • Core loop

交付物

一页游戏简报、验收条件与项目约束。

检查点

每项需求都能对应到可观察的玩家行为。

推荐工具

  • Level Design Book · unofficial design skill
02
开发步骤

选择引擎

根据平台、编程语言和编辑需求选择引擎，为代理提供固定版本、官方 API 和可运行的起点。

重点

确定开发基础

主题

  • Godot
  • Phaser · Unity

交付物

固定引擎版本、用一条命令即可启动的最小项目。

检查点

在干净环境中能够导入、运行和构建项目。

推荐工具

  • Godot Engine · Official Documentation
  • Phaser · First Game Guide
  • Unity · Manual
03
开发步骤

实现游戏循环

逐步实现移动、交互、计分和重启，每次修改后都运行游戏并检查截图，逐渐连接成可玩的循环。

重点

先让它可玩

主题

  • 编程代理
  • Game logic

交付物

可玩的垂直切片，以及可重复执行的测试输入。

检查点

玩家能够开始、获胜或失败，并在正确的状态转换后重新开始。

推荐工具

  • Godot Demo Projects
  • Phaser · Examples
  • Unity · 2D Tech Demos
04
开发步骤

制作美术资产

生成或寻找资产前，先确定美术方向、精灵尺寸、帧数和锚点；导入时检查透明通道、碰撞形状和动画状态。

重点

建立视觉风格

主题

  • Sprites
  • Tiles · Audio

交付物

资产清单、动画状态表和许可记录。

检查点

各帧比例一致，碰撞与画面相符，来源有据可查。

推荐工具

  • PixelLab AI Agent Toolkit
  • Scenario
  • ElevenLabs Sound Effects
05
开发步骤

试玩与迭代

结合脚本输入、状态断言和关键截图，分别记录构建、玩法与视觉问题，再邀请玩家试玩并调整节奏。

重点

调整体验与节奏

主题

  • Benchmarks
  • Visual QA

交付物

输入回放、关键画面和玩法验收结果。

检查点

失败、暂停、重启和长时间游玩都有相应测试记录。

推荐工具

  • Playwright Test
  • GUT · Godot Unit Test
  • Unity Test Framework
06
开发步骤

发布游戏

为目标平台构建，检查资产路径、控制和加载，记录依赖版本、生成提示词和已知限制，为后续迭代保留上下文。

重点

交到玩家手中

主题

  • Build
  • Player feedback

交付物

可分发构建、README 和发布说明。

检查点

目标设备上的玩家能够启动、加载、游玩并反馈问题。

推荐工具

  • itch.io
  • CrazyGames
  • Steam
