开发路径

探索代码世界模型

定义状态与动作，连接渲染，并检查世界中哪些信息会持续保留。

代码世界模型

Code into living worlds

项目预览

  • StreamRender-H3 · Engine to neural render
  • SolarRenderer · Voxel world, reimagined
01
开发步骤

定义世界状态

明确世界由代码、显式场景还是视频潜变量表示，分别评估可编辑性、可解释性和视觉质量。

重点

确定状态的权威来源

主题

  • Code state
  • Scene graph

交付物

状态结构、表示方案与可控变量。

检查点

位置、碰撞、物体身份和事件分别由哪个系统负责，已有明确答案。

推荐工具

  • WorldCoder
  • Programmable World Model
02
开发步骤

连接动作接口

定义动作空间与环境接口，区分语言命令、键盘输入和相机轨迹，让模型控制与预期交互一致。

重点

让输入引起状态变化

主题

  • Action interface
  • Environment

交付物

动作协议与环境 step 接口。

检查点

动作含义清晰，从输入到画面的路径能够被测试。

推荐工具

  • DIAMOND — Diffusion for World Modeling
  • SolarWM
03
开发步骤

编写世界动态

探索表达状态转换和奖励的程序，或由代理更新环境的方法，检查长期状态、物体持续性和编辑能力。

重点

保留规则与记忆

主题

  • WorldCoder
  • Code world model

交付物

状态转换规则、场景更新代码与状态日志。

检查点

状态变化可以复现，规则可独立于渲染画面检查。

推荐工具

  • WorldCoder
  • Code World Model: Coding Agent as World Brain
04
开发步骤

渲染世界

将引擎结构条件传给神经渲染器，分别检查几何、动作对齐、时间一致性和推理延迟。

重点

从结构到图像

主题

  • SolarRenderer
  • StreamRender-H3

交付物

结构输入、神经渲染输出与同步日志。

检查点

画面随时间跟随底层状态变化，而不只是单帧看起来正确。

推荐工具

  • SolarRenderer
  • StreamRender-H3
05
开发步骤

检查一致性

测量长期漂移、动作响应、物体身份和碰撞，区分项目演示、论文评估与可复现的开放实现。

重点

测量哪些状态能被保留

主题

  • Long horizon
  • Controllability

交付物

固定动作序列、对照录像与评估报告。

检查点

记录持续时间、分辨率、硬件和失败，使比较采用等价条件。

推荐工具

  • GIF-MCTS / Code World Models Benchmark
  • Code World Models for General Game Playing
06
开发步骤

做成交互体验

结合模型许可、计算成本和实时要求，选择研究演示或产品原型，保留可复现配置与限制说明。

重点

让研究可以被操作

主题

  • Runtime budget
  • 研究演示

交付物

交互演示、环境说明与已知限制。

检查点

目标硬件能够持续承担延迟、内存与计算开销。

推荐工具

  • DIAMOND — Diffusion for World Modeling
  • WonderWorld
